# 身份证数据移除实施计划

> **执行要求：** 使用分任务实施与完成前验证流程；生产数据库及历史文件删除前必须取得用户一次明确确认。

**目标：** 身份证不再属于竞迹的数据模型、接口、页面和导入导出流程；以兼容事务迁移移除已有字段及相关内容。

**架构：** 保留既有运动员、账号 ID 和出生日期、性别；新库不创建身份证字段。旧库必须先运行独立备份迁移工具，应用启动不得悄悄清除旧字段。历史备份独立管理。

**技术栈：** React、微信小程序、Express、Node.js 内置 SQLite、现有 Excel 工具。

**需求来源：** 本任务用户提供的《身份证号字段与业务逻辑彻底清理 Mini Spec》。

## 影响清单

| 范围 | 文件或结构 | 处理 |
| --- | --- | --- |
| 数据库 | `registration_requests.identity_number`、`athlete_profiles.identity_number` | 备份后事务删除，保留其余列、主键与关联 |
| 历史内容 | 导入条目 JSON、审计详情及自由文本 | 递归清除明确身份证键；候选号码只在安全规则下清除，不输出值 |
| 初始化 | `server/core/db-initialize.ts`、`db.ts` | 新库不建列；旧库启动前阻断并要求先迁移；删除身份证生日推导 |
| 档案 API | `server/athlete/athlete-module.ts`、`athlete-routes.ts` | 删除请求、校验、SQL、响应字段 |
| 注册审核 | `server/access/` | 删除历史响应和空值写入；保留审核、角色、队伍关联 |
| 导入导出 | `server/data-import/`、模板生成脚本及公开 XLSX | 移除列、解析、写入与说明；旧列不进入暂存 payload |
| Web | 运动员管理、专项搜索、类型及测试 | 删除输入、搜索和字段，生日性别独立维护 |
| 小程序 | 档案编辑、展示、payload、format 及测试 | 删除输入、展示、脱敏函数及提交白名单 |
| 历史文件 | `outputs/`、`tmp/`、旧库副本、已有备份 | 先仅登记元信息；根据确认范围处理，不自动销毁历史备份 |

当前只读结构检查未发现身份证列的专用索引、约束、视图或触发器。`idx_athletes_identity` 是姓名、项目、队伍索引，保留。

## 备份与历史副本边界

运行目录有主库、测试或演示库、多份 `data/backups/` 旧备份及旧重建快照。主库迁移不会清除这些副本。新迁移备份也含待清除的历史数据，须限定访问、登记用途、保留期限及责任人；加密归档或销毁需要明确方案。文件系统快照、SSD 和外部服务器副本不能仅凭 SQLite VACUUM 宣称已物理抹除。

未确认前不读取真实业务记录、不修改或删除这些文件。公开模板可在隔离测试中生成新版本；历史导出或带数据工作簿必须先明确范围，不因文件名包含“模板”便假定没有真实资料。

## 回滚

事务失败直接回滚；提交后的恢复需维护窗口和经校验的备份，并恢复兼容的旧应用。恢复会重新引入身份证数据，因此必须明确授权并防止覆盖迁移后新增的业务记录。
