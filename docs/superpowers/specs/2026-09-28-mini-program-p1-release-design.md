# 微信小程序 P1 上线加固设计

## 目标

保护运动员照片和登录会话，并让弱网或重复触控下的核心小程序流程可恢复、可理解、不可越权。

## 范围

### 安全链路

- 证件照从公开静态资源改为按运动员访问范围鉴权的读取接口，响应禁止缓存。
- 上传照片按真实 JPEG/PNG 内容校验、解码与重编码，不信任客户端 MIME。
- 为用户维护会话版本；JWT 携带该版本，服务端每次认证核验。改密、退出登录和停用账号均使旧 Token 失效。

### 小程序可用性链路

- 核心表单页面在加载失败后提供显式重试；保留已有请求竞争护栏。
- 训练记录删除在请求期间锁定当前记录，避免重复删除。
- 教练在既有项目范围内选择授权队伍，并按姓名或队伍搜索可访问运动员；运动员不能使用这些范围扩展控件。

## 架构

照片继续在同一 HTTPS origin 下使用相对 URL，但路径改为 `/api/athletes/:id/photo`，服务端先执行 `requireAuth`、`hasAthleteAccess`，再读取受控文件并返回正确的图像类型与 `Cache-Control: no-store`。上传使用图像解析库的解码结果重编码为服务端选定格式；不再由 MIME 决定磁盘扩展名。

用户数据增加单调递增的 `session_version`。登录签名时包含版本；`getAuthUser` 从数据库读取当前用户和版本并拒绝旧 Token。退出小程序调用受认证的注销接口后清理本地缓存；改密与停用路径也递增版本。

小程序在现有 `loadWithGuard` 与 `scope-filter` 上扩展，不让页面手工拼接权限范围。队伍候选来自登录态 API，服务端继续验证 `teamId`；关键词只过滤已授权的客户端候选列表。

## 兼容性与错误处理

- 已存照片路径迁移为可从文件名解析的受保护读取，不更改数据库中的历史路径。
- 老 JWT 不含会话版本时视为已失效，用户重新登录即可恢复。
- 上传格式或图片内容不合法返回明确 400，客户端显示可重试错误。
- 重试仅重发用户明确发起的加载请求，不自动重复写操作。

## 验证

- API 回归验证：无 Token/跨运动员读照片 401/403、授权用户可读、伪造 MIME 拒绝、改密/注销后旧 Token 401、教练跨队 `teamId` 403。
- 小程序测试验证：失败页有重试入口、删除锁、队伍/搜索的授权候选行为。
- 执行 `npm test`、`npm run mini:typecheck`、`npm run api-check`、`npm run check`、`npm run lint`。
- 真机验证：照片上传/重开、Token 失效回登录、断网重试、教练队伍筛选与移动网络。
