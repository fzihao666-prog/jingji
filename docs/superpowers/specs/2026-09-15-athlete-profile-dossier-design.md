# 运动员综合档案整合设计

## 目标

在既有 `personal` 页面内，将当前选中运动员的档案整合为单页综合视图。页面始终服从现有全局项目、日期范围、选人逻辑和服务端访问范围；不新增一级页面、平行数据模型、医学判断或模拟数据。

## 范围与非目标

页面按“个人信息、制胜要素分析、训练情况、生理生化与恢复状态、个人 vs 团队对比”顺序呈现。

- 保留并嵌入身体成分、FMS、伤病恢复、体能测试录入与 PDF 导出。
- 将所有“运动员表现”用户可见文案替换为“体能测试档案”。
- 生理生化没有正式模型前仅展示“暂无数据”，不构造指标或趋势。
- 不改变既有角色权限、选人范围、项目隔离、伤病录入能力或专项测试的艇组结果语义。

## 架构

新增一个服务端档案查询服务，负责读取和比较，不写入正式训练事实。`server/index.ts` 仅负责认证、参数解析、运动员访问范围校验和调用该服务。前端仅通过 `src/api.ts` 获取类型化数据，`PersonalPage` 组合卡片并展示空状态。

```text
PersonalPage
  -> src/api.ts
    -> /api/athletes/:id/wellness-trends
    -> /api/athletes/:id/profile-comparison
    -> /api/special-tests?athleteId=&from=&to=&project
      -> requireAuth + athlete access scope
        -> athlete-profile-service
          -> daily_wellness / training_sessions / 测试与身体成分表
          -> buildOverviewPayload 的既有训练汇总口径
```

服务端从目标运动员的真实 `team_id` 与 `project` 确定比较队列。前端不以队伍名称拼接成员，也不计算团队均值。

## 数据口径

所有新增查询只接受当前全局项目和日期范围内的数据，且排除 `is_demo=1`、演示/估算来源和质量不合格记录；无有效值使用 `null` 或空数组，绝不以 0 表示缺失。

### 恢复趋势

恢复趋势返回日期、个人值、团队日均、样本数与来源/质量标记，包含 `daily_wellness` 的无训练日报。RPE 可关联当天有效训练课次；睡眠、晨脉与体重直接来自日报。缺失日期保持缺失，不填 0。

### 测试、身体成分与 FMS

身体成分当前值取结束日期前最近的有效实测，历史趋势只使用全局周期内记录。FMS、体能测试与身体成分比较只在相同测试日期或服务端显式允许的测试窗口内返回团队均值。结果携带单位、样本数和数据日期；不足两名可比运动员时只返回个人值及不可比原因。

有氧耐力由既有指标字典与有效测试记录动态识别，例如 `VO2Max`、一般耐力或已采集心率类指标；不将项目专属指标写死到页面。

### 专项测试

`/api/special-tests` 添加可选 `athleteId`，仅返回成员列表包含该运动员的事件结果。展示艇组成绩、名次、个人既往最佳与阶段变化，不把艇组成绩换算为个人成绩或个人团队平均。

### 训练与团队比较

体能训练、专项训练与训练量比较复用 `buildOverviewPayload` 的有效课次与团队去重规则。个人 vs 团队摘要固定比较同项目、同队、同周期、同单位且至少两名可比运动员；每项包含个人值、团队均值、差异、样本数和日期或日期跨度。

冠军模型继续独立显示；模型未配置时显示“模型数据待配置”，不承担团队比较职责。

### 伤病恢复

伤病模块将支持传入页面结束日期：当前状态选择该日期及之前的最新记录；病史始终返回全量并标注“历史记录”，不按全局周期截断。

## 前端结构

`PersonalPage` 保留现有运动员选择与首屏档案卡，改为下列区域：

1. 个人信息：头像、姓名、项目、队伍、教练及已有字段；缺失使用“未填写”或“—”。
2. 制胜要素分析：身体成分、FMS、专项测试、体能测试档案、有氧耐力和冠军模型空状态。
3. 训练情况：体能训练与专项训练两张卡，展示规定汇总与日趋势。
4. 生理生化与恢复状态：固定生理生化空状态、RPE/睡眠/晨脉/体重趋势，以及伤病与恢复。
5. 个人 vs 团队对比：展示比较范围、样本数、单位、数据日期和不可比空状态。

原有 `BodyCompositionModelOverview`、`FmsPersonalChart`、`StrengthProfileModule`、`InjuryRecoveryModule` 继续负责各自的既有交互；页面仅提供统一范围数据与布局。现有未提交的个人信息首屏改动作为保留基础继续演进。

## 错误与权限

新增路由复用既有认证与运动员访问范围校验。无权访问返回既有授权错误；合法但无数据返回空结构。前端读取失败只显示该卡片的错误/空状态，不能回退为模拟数值。

## 验证

- 为新服务的有效数据过滤、同队比较阈值、单位/日期不可比、无训练日报与专项成员筛选编写测试并先观察失败。
- 运行已有专项测试定向检查。
- 执行 `npm run check` 与 `npm run build`。
- 手动核查：运动员账号仅见本人；不同项目和队伍不会参与比较；缺失数据显示为空状态；体能测试录入和 PDF 导出仍可用。
