# 运动员筛选与专项测试联动设计

## 目标

统一“体能训练”和“专项训练”首页的运动员选择方式。两个页面默认展示当前项目、权限范围、队伍范围和统一周期内的团队分析；用户在页面底部选择运动员后，当前页原地切换为个人分析，同时保留同口径团队基准。刷新页面或清除选择后恢复团队视图。

本次不新增模拟数据、不改变全局项目或时间筛选，也不改变现有专项测试导入流程。

## 范围与状态

每个首页分别维护临时的 `athleteId: number | null`，初始值固定为 `null`：

- `null` 表示团队视图；不默认选中任何运动员。
- 点击页面底部的运动员卡片后，将本页 `athleteId` 设为该卡片 ID。
- 点击“全部运动员”或标题旁的清除按钮后，恢复为 `null`。
- 该状态不写入 URL、全局应用状态或持久化存储，因此刷新后自然恢复团队视图，且两页间不互相带入筛选。

体能训练页面移除顶部运动员下拉；专项训练页面保持顶部项目、时间和队伍等全局筛选，不增加顶部运动员选择器。

## 运动员区域

两个页面末尾均提供“运动员”区域，结构为搜索框、团队视图复位按钮和固定高度的可滚动运动员卡片列表。容器高度以约五张卡片为默认可见量，超出的已授权运动员通过滚动访问。

列表只能使用当前登录用户已获授权、当前项目匹配且符合当前队伍范围的运动员。搜索在这份已授权列表内进行，至少按姓名匹配；当已有字段可用时，同时按运动员编号、队伍和小项匹配。搜索不触发新的越权查询。

卡片是可操作的原生按钮或等价的语义化控件，具备键盘激活、清晰焦点样式和选中态。无真实字段时显示“未录入”，不生成假数据。

- 体能卡片优先展示训练课次、时长、SRPE 负荷及已有核心体测摘要。
- 专项卡片优先展示课次、时长、距离、负荷和最近专项测试成绩。

## 分析接口与权限

专项训练首页的概览接口扩展为接受可选 `athleteId`。服务端在查询前验证：

1. `athleteId` 是有效整数且位于当前用户可访问范围；
2. 运动员属于当前项目；
3. 当指定队伍时，运动员属于该队伍；
4. `from`、`to` 和现有团队范围保持有效。

当未传 `athleteId` 时，响应维持团队分析。传入时，响应同时包含：个人训练分析、同项目/同队伍/同周期的团队基准、该运动员可见的最近专项测试，以及对应团队测试基准。团队基准不能因选中个人而缩小为单人。

体能训练沿用已有真实训练和测试读取链路；其个人范围与团队基准在前端按相同项目、授权范围和日期范围分别计算。若当前实现缺少足以安全计算团队基准的字段，应在服务端补充已授权范围数据，而不是依赖未校验的前端输入。

## 页面表现

团队模式展示团队统计、均值、趋势、结构及已有排名等内容。个人模式维持相同页面结构，但可联动模块改为当前运动员的数据，并在关键指标中显示“当前运动员 / 团队平均 / 差异”。

选中后，页面标题附近显示“当前运动员：姓名”及清除按钮，让用户在页面上方也能确认当前范围；不重新引入完整运动员下拉框。

专项训练个人模式新增“专项测试表现”卡片：使用当前项目、队伍和 `from`/`to` 内该运动员最近一次有效专项测试，显示成绩、团队均值和差异。若没有可见测试或不足以形成团队基准，明确展示缺失状态，不以零或估算值替代。

所有训练、趋势、结构、团队均值和专项测试均严格复用页面的 `from`、`to`、项目和队伍范围。

## 错误处理

前端仅在已授权运动员列表中筛选；服务端仍是最终授权边界。越权、跨项目、跨队伍或无效 `athleteId` 请求返回明确错误。概览请求失败时继续使用页面现有加载、错误和重试状态，不展示过期个人分析作为当前结果。

## 验证

实现应新增或更新以下自动化验证：

- 专项概览接口接受合法个人筛选，并拒绝越权、跨项目、跨队伍和无效 ID；
- 个人训练统计与团队基准使用相同周期，但团队基准不被缩小为单人；
- 个人专项测试取当前周期内最近有效记录，并正确计算团队均值与差异；
- 两页默认团队视图、搜索、选择、清除、项目/队伍联动和键盘选择行为；
- 运行 `npm run check`、`npm run lint`、受影响的 Vitest 测试及 `npm run special-training-check`。

## 非目标

- 不将运动员选择跨页面共享或持久化。
- 不新增、伪造或以零填充训练与测试字段。
- 不改变专项测试导入、训练计划和个人档案页面的业务流程。
