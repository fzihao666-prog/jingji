# 微信小程序 P0 上线修复设计

## 目标

使仓库中的小程序构建使用生产 HTTPS API，并消除注册审核关闭时的匿名跨队伍教练开户路径。同步恢复能阻止这些问题回归的检查。

## 范围与非目标

本次只修改小程序发布配置、注册审核的服务端授权，以及对应自动化测试和检查脚本。不会修改生产 Nginx、证书、微信公众平台服务器域名、正式 AppID 归属或隐私主体资料；这些均需在部署环境和公众平台完成验收。

## 设计

### 小程序发布配置

`WeChat Mini Program/config.js` 固定使用 `production` 和现有唯一 HTTPS 基础地址，保留 `NETWORK_DEBUG=false`。现有 `config.test.js` 继续作为发布门禁，明确断言生产地址的解析结果。开发联调通过本地未提交覆盖或受控构建流程完成，不能将 `127.0.0.1` 提交为默认发布配置。

### 注册审核授权

注册审核开关是全局安全策略，只允许 DMD 修改。关闭审核不再允许匿名 `POST /api/auth/register` 自动激活教练账号：匿名注册在关闭审核时仅可自动激活 ATL，教练申请保持 pending，必须由有对应项目/队伍范围的审核人批准。审核激活已存在的范围检查保持不变。

这会避免普通 SCC 关闭审核后，使匿名请求直接获得任意项目、任意队伍的 SCC 权限；也保留运动员在明确关闭审核时的低摩擦开通能力。

### 回归检查

为注册路由补充集成测试，覆盖：非 DMD 修改开关返回 403、DMD 可修改、关闭审核时 ATL 自动激活、SCC 仍待审核、审核人只能批准自身权限范围内申请。更新小程序日常待办检查所需的依赖 mock，恢复 `npm run api-check`。

## 错误与兼容性

现有待审核教练申请不改变状态；关闭审核后新提交的教练申请将得到明确的待审核成功响应。客户端已能根据 `status: pending` 显示审核提示，无需引入新页面或协议字段。

## 验证

运行 `npm run mini:typecheck`、小程序相关 Vitest、注册/权限覆盖测试、`npm run api-check`、`npm run check` 和 `npm run lint`。上线前仍必须在正式 AppID 的真机 Wi-Fi 与移动网络中验证 HTTPS、request/uploadFile/downloadFile 合法域名、登录和照片上传。
