# 竞迹数据导入模块优化 Spec

- 日期：2026-10-22
- 状态：待实施；本文完成不代表功能已经实现。
- 适用范围：Web 统一导入、模板下载、统一导出，以及独立体能/专项入口的一致性改进。
- 目标用户：有相应项目和队伍权限的教练及管理者。

## 1. 目标与现状

目标：教练选好项目、队伍和填写用途，取得带队员身份的模板，只填写本次实际记录；上传后能理解错误、直接修正，并在明确新增或更新结果后一次确认入库。

依据当前 `DataImportPage.tsx`、`data-import-routes.ts`、`data-import.ts`、模板构建器、共享字段字典、权限模块和定向测试核对现状：

| 已有能力，继续保留 | 本次需要补齐或修复 |
| --- | --- |
| 分用途模板预填人员；中文测试项目；固定枚举下拉 | 统一模板也预填人员；下载支持队伍和人员子集；教练不填写内部代码 |
| 必填靠前、选填靠后，颜色与文字并用 | 选项及必填规则在模板、网页和服务端一致；下拉覆盖实际录入规模 |
| 无单元格点击提示和表头批注 | 解释集中在表头、填写说明和网页可见区域，保持无弹出注释 |
| 人员消歧、项目权限、草稿、事务提交及并发复核 | 在线纠错覆盖错误源字段；重新解析失败保留草稿；预览读取也复核当前权限 |
| 正式数据按业务键去重，重复提交有回执 | 文件去重按上传账号隔离，不阻断另一位有权教练处理同一文件 |
| 新模板显式日期；空白和真实0分别处理 | 旧文件也不静默补当天；统一展示日期来源 |

当前风险：`ensureMetricDefinitions()` 在解析和提交时更新部分内置指标定义并设 `active=1`；重新解析在完整解析成功前删除旧批次；同文件同项目查重未先按创建账号裁剪。以上列入第一阶段。

### 与现有规格的关系

本文是整个导入模块的后续优化规格。已完成的模板视觉约束继续遵守 `import-template-simplification-mini-spec.md`，特别是全部数据列可见、选填后置、中文下拉和不弹出批注。

旧 `openspec/changes/simplify-coach-data-import/` 仍含与当前实现不一致的“默认只补空、覆盖另行确认”规划。本文明确采用当前产品规则：**本次非空值更新已有值，空白保留，真实0正常写入，提交前展示差异并统一确认**。实施本文时先同步冲突条款，不把旧任务勾选状态当成实现事实；不增加逐字段覆盖审批。

## 2. 成熟产品案例及采用边界

以下为官方文档中的可借鉴交互，不表示竞迹引入这些服务，也不据此宣称性能或效果。

| 案例与来源（查阅日期同本文） | 可借鉴做法 | 竞迹落地规则 |
| --- | --- | --- |
| [Flatfile 导入流程](https://support.flatfile.com/articles/7763163677-importing-data-with-flatfile-overview) | 校验后提供在线编辑、错误筛选和批量修正 | 异常优先；错误附修正入口；官方模板自动映射，不让常规用户多走映射步骤 |
| [Airtable CSV 导入](https://support.airtable.com/docs/csv-import-extension) | 按唯一字段匹配，提交前预览新增、更新和无变化记录 | 编号优先定位人员；业务键定位事实；预览统计与回执可核对 |
| [CSVbox 列设置](https://help.csvbox.io/sheet-settings/columns) | 区分机器字段标识、面向用户的列配置及必填校验 | 内部标识留在系统；教练看到中文名称、条件、单位和示例；同一规则驱动呈现与校验 |

不采用案例中不适合体育事实的行为：重复来源不能只取第一行；无效值不能无提示丢弃；未知选项不能自动新增为正式指标；不把备注、时间推断或 AI 建议当成实测结果。网页错误直接可见，Excel 不使用悬停/点击注释。

## 3. 用户流程

```text
准备填写：选择用途 → 选择授权队伍/队员 → 下载预填模板
                                      ↓
已有文件：上传 → 检查人员及字段 → 修正错误 → 核对新增/更新 → 确认 → 查看回执

历史查询：选择范围 → 导出历史数据（与填写新数据明确区分）
```

- 页面主操作为“下载填写模板”“上传文件”“导出历史数据”；用途在模板准备区选择，不平铺五个同级下载按钮。
- 用途包括队员资料、训练记录、测试成绩、统一模板；保留独立体能及专项入口，名称说明用途与数据范围。
- 保留当前四步进度；已有队员唯一匹配且无异常时自动通过人员确认，一次最终确认即可入库。
- 草稿恢复回到上次处理位置；存在未保存修改时保留离开提示。切换项目后旧请求不能覆盖新项目的名单或批次。
- 下载之前显示项目、队伍、人员数及“仅预填身份，成绩留空”；无授权队员时显示空模板选项及建队前置说明。

## 4. 模板和导出规则

### 4.1 人员范围与预填

1. 统一模板与分用途模板使用同一授权名册服务。默认范围是当前项目内的授权在训人员；队伍未确定且存在多队时，明确显示“全部授权队伍”，允许缩小范围。
2. 支持选定一个授权队伍、选择队员子集或全部队员。项目、队伍和人员参数均由服务端复核；含范围外ID时拒绝，不悄悄过滤后声称全部成功。
3. 在适用业务表预填编号、姓名；原字段包含项目或队伍时同步填写，不要求教练自行补内部编号。提供可见队员名册供核对，不新增身份证号、手机号或历史伤病等预填内容。
4. 每人先提供一行身份；多次测试、多课、多组由用户复制身份行后填写，按既有日期、课次和组序规则识别。多人艇不预造组合及成员关系。
5. 只有身份信息而无实际业务变更的行不生成业务事实；不因预填项目、队伍或名册而批量创建空记录。已有人资料中的预填身份字段不视为档案更新；新姓名按新建规则确认。
6. 有权但尚无人员可下载空模板；无有效队伍时仍可准备模板，正式导入前按现行规则要求有效授权队伍。

### 4.2 字段呈现与选项

- 所有业务列直接显示；身份及必填在前，常用选填其次、专业选填最后；保留现有冻结、颜色及文字标记。
- 表头直接写明条件、单位/日期格式和示例；不显示冗余“无单位”，不放可导入的示例记录，不生成表头批注或点击单元格输入提示。
- 真正有固定字典的字段采用下拉。项目、队伍、测试项目按上下文和授权裁剪；状态、等级、侧别、完成状态等使用已有合法枚举。
- 内部指标代码和动作代码不作为教练必填项；已有字典支持的名称由系统解析。没有动作字典的自由动作名保持文本，不臆造一套受限动作选项，也不要求教练填写代码。
- 训练内容、备注、伤病描述、评分依据等无固定字典字段不强制转成枚举。队内评分协议只有已有配置可选时才下拉，否则按真实使用的标准名称填写并附通俗示例。
- 下拉预设范围为 `max(500, 预填人数 + 200)` 行；超出时说明复制已有格式行的方法。范围是呈现能力，服务端仍校验全部有值行。
- 长选项通过命名区域引用可见选项表，不依赖超长内联列表。停用或同名歧义指标不出现在有效选项中；找不到时指向有权限的字典管理员处理。
- 名称带单位，例如“纵跳（cm）”；填45表示45厘米。模板内字典仅供填写，上传时服务端读取正式有效字典，不能相信用户改过的选项表。

### 4.3 新填写与历史导出

| 操作 | 数据与用途 |
| --- | --- |
| 下载填写模板 | 授权身份预填，成绩、日期和恢复状态等本次记录留空；用户明确选择日期后才可带入日期 |
| 导出历史数据 | 明确标为历史数据，默认保留当前现有的完整字段与往返能力；页面显示当前范围，修改后重传会更新已有事实 |

本期不并行引入第三种历史编辑文件格式。历史导出保留内部字段时注明其为完整数据格式，解析继续兼容，不把它宣传为首选填空模板。后续如增加“历史修改模板”需独立定义不丢字段的往返契约。

## 5. 解析、人员和日期

- 官方模板按稳定字段标识和受控别名直接识别，保留旧表名、列重排、XLS/XLSX 兼容；不增加必经的任意文件字段映射步骤。
- 重复表头、必需列缺失、含业务数据但无可定位人员、未识别的有内容工作表需要明确提示；说明页、名册和选项表明确识别为辅助页，不作为业务错误。
- 未识别表含数据时，提交前需确认忽略该表；不以普通绿色成功信息掩盖遗漏。空表与只有预填身份的行自动忽略并计入“未填报”，不计作错误或正式跳过记录。
- 人员识别保持编号优先，再用项目、队伍和姓名消歧。编号与姓名矛盾、同名多身份、跨队/跨项目不能静默选择。当前无权限人员的姓名、所属队伍等不能通过候选或错误详情泄露。
- 最小建档只要求姓名、当前项目和有效队伍；不新建登录账号、不推断生日和性别。已有人员不通过导入调队，恢复停用人员沿用现有独立权限及确认规则。
- 所有业务日期只来自行内有效值或用户明确选择的统一日期；旧文件取消静默使用当天。保留既有旧格式日期解析，但展示可追溯的日期来源；非法非空日期不能被统一日期覆盖。
- 日期来源以“文件填写/统一日期/旧格式解析”标识；出生日期永不补填，切换日期参数不静默改变既有草稿，需选择重新解析。
- 中文测试项目按当前项目有效字典精确解析，已确认的内置别名可归一。同名不同单位须选择完整名称；仍有歧义必须阻断；不自动建指标或静默换单位。

## 6. 在线校对与错误处理

### 6.1 规则模型

共享纯字段定义补充 `fieldKey`、中文标签、输入类型、选项引用、条件、单位和允许修改范围；数据库字典查询和权限判断仍位于服务端。模板、网页编辑器和服务端校验读取同一业务规则，避免“模板选填，提交却必填”。

每个问题至少包含：错误代码、严重性、业务类型、工作表、原始行列、中文字段名、原值、原因、可执行修正建议、允许操作。原值与最终值分开保留；多指标来源行可以定位到独立单元格。

### 6.2 修正行为

- 默认显示阻断错误，支持按人员、工作表、业务类型和错误原因筛选；常规有效记录无需逐条点击确认。
- 姓名/人员关联、日期、数值、测试项目和枚举等提供匹配的编辑器；错误信息显示在对应字段旁，不依赖红色或鼠标悬停。
- `invalid_row` 仅在原行及字段仍可确定时支持在线修复，修正后由服务端重新生成对应领域记录；文件损坏、结构无法定位等问题提供重传入口，不伪装成可编辑成绩。
- 重选测试项目必须重新校验单位、侧别、协议及业务键，清除旧选择造成的解析错误，但保留来源与修改审计；普通payload修改不能直接清除阻断标记。
- 一次原始行修正会重算该行派生记录，不能只修改其中一项就把同行其他错误清掉。改变人员或日期后重新分组检查重复。
- 支持给选定错误行设置明确统一日期等有限批量修正；先预览受影响条数，不提供跨人员批量套用成绩、RPE或组次重量。
- 修改自动保存，显示保存中/已保存/失败；错误未全部解决也可暂存。未保存、保存失败、仍有阻断错误时不能提交。
- 问题清单使用中文记录类型并包含修正方法。首次交付仍定位为诊断清单，不承诺其可原样回传；原始模板修复或页面纠错后提交。

## 7. 数据更新、字典与草稿安全

### 7.1 唯一更新语义

- 本次导入非空字段更新对应已有事实；空白不清空已有数据，0与“未完成”正常保留。不存在以空白删除正式值的入口。
- 同文件相同事实的相同值或互补值可按既有规则合并；不同值必须人工选择，不取平均、不按行顺序取第一项。
- 正式事实仍以现有业务唯一键定位，测试指标、侧别、协议、多课和多组不混淆；导出重传不因重新分类产生新事实。
- 提交前展示新增、更新、无变化、排除、未填报和阻断错误；人员统计与业务记录统计分开。更新明细展示提供字段的旧值→新值，保留一次最终确认，不新增逐字段审批。
- 建档与业务写入继续同事务；失败整体回滚。提交时复核当前权限、人员状态、业务快照和字典定义；预览后字典停用、单位或关键归属变化应要求刷新校验，不能继续按旧定义写入。
- 重复提交返回该批次首次实际回执，重复上传使用正式业务键再判断；回执数量以实际写入结果为准。

### 7.2 字典只读

导入解析、预检、重试和提交不得修改指标名称、单位、启停状态、范围或建议区间。字典初始化移出业务请求，只补缺失项；既有管理员配置保留。初始化、解析和提交失败的回归测试必须比较字典前后完全一致。

### 7.3 草稿与文件去重

1. 文件复用按创建账号、项目、文件内容识别。查找历史文件时先约束账号；同文件另一账号创建独立批次，不返回或暴露对方批次。
2. 新文件键使用带版本的账号作用域哈希，继续满足现有 `(file_hash, project)` 唯一约束；只在本人范围兼容查找旧原始哈希批次，不为本项重建历史表或改写历史主键。
3. 同账号未提交文件可继续草稿或明确重新解析；已提交文件保留原批次并新建解析批次，允许补回缺失事实。
4. 重新解析先完成读取、结构/额度检查及候选构建，再在短事务中替换本人的待确认草稿。失败、断网或并发冲突不删除旧人员映射及校对结果；成功替换前说明旧校对将被替代。
5. 草稿引入递增修订号，保存、重新解析与提交绑定已见修订；过期修改返回409并提示刷新。可在既有批次元数据中兼容保存，旧批次初始视为0，不要求迁移正式事实表。
6. 批次读取、错误下载、校对及提交都复核当前授权；撤权后本人旧草稿也不能继续泄露范围外人员。权限不足时保留服务端草稿，不自动删数据。

## 8. 体育业务最小填写集与计算口径

在人员及真实业务日期明确后，遵守以下最小输入，不新增科学阈值：

| 业务 | 最小输入及条件 | 系统承担 |
| --- | --- | --- |
| 新队员 | 姓名、项目、有效队伍 | 编号与合法关联；不补虚构身份 |
| 训练课次 | 实测时长min或距离km之一；多课须课次定位 | 有时长及RPE才计算SRPE；缺RPE允许入库 |
| 力量组次 | 动作、实际次数、实际外加重量kg；多组/多课须归属 | 按有效实际组次计算训练量，不把计划数当结果；徒手真实外加重量可为0 |
| 每日恢复 | 至少一项实际数值或明确状态 | 沿用现有量表；状态不推断实测数值 |
| 身体测量 | 至少一项实测值 | 复用正式身体事实源；恢复体重不冒充身体测量 |
| FMS | 至少一项0—3整数，未测留空 | 七项齐全才形成完整21分总分 |
| 体能/其他测试 | 中文项目及实测成绩；按既有规则补协议/侧别 | 代码、单位和合法范围；不静默换算 |
| 伤病 | 真实名称、部位，疼痛可空 | 不把未提供当无痛；状态/侧别沿用既有语义 |
| 竞技评估 | 有依据的评分；规定单项需真实协议；竞技状态总分沿用非空约束 | 不编造总分、评分表、等级或冠军标准 |
| 专项成绩 | 项目、距离m、人员或完整组合、至少一轮有效成绩 | 有效轮次的平均/最好；仅在相同可比条件排名，缺组别为未分组 |

赛艇、皮划艇、激流按各自指标适用范围处理；不要求激流填写平水项目特有数据。课次km与专项m保持各自单位；左右侧和多人组合不合并为一个不明归属的事实。无数据、无效值与真实0分别保留。

## 9. 技术边界与接口演进

### 9.1 在现有架构内实施

- `shared/`：纯字段/选项/错误契约、业务唯一键与归一化；不引入DB或HTTP依赖。
- `server/data-import/`：授权名册、模板生成、领域解析、草稿重校验、事务提交及导出。优先从现有大文件抽取本次需复用的逻辑，不做全模块重写。
- `src/api.ts`：统一封装请求；`DataImportPage.tsx` 负责编排，字段编辑器使用项目现有组件及样式变量。
- 独立体能/专项保留正式写入链路，共用字段描述、授权规则和错误格式，不在第一阶段强行合并存储或会话模型。
- 正式训练继续写入 `training_sessions`、`daily_wellness`、`strength_result_sets`；其他业务沿用已有事实源。无第二套训练数据源，无AI推断成绩，无外部导入SaaS运行时依赖。

### 9.2 契约范围

| 现有接口 | 拟增量行为 |
| --- | --- |
| `GET /api/data-import/template` | 保留kind/project及旧无参空模板；增加单队伍与人员子集参数，统一模板使用同一授权预填服务；无参响应不含真实名册 |
| `GET /api/data-import/export` | 保留完整往返文件；明确历史范围与修改回传语义 |
| `POST /api/data-import/analyze` | 保留上传与继续草稿方式；原子重解析、账号隔离查重；返回日期来源及问题摘要 |
| `GET /api/data-import/batches/:id` | 保留现有预览兼容；补修订号、当前授权检查和统一统计 |
| `PUT /api/data-import/batches/:id/items` | 增加受控原始行修正和字段重校验；只允许该类记录可修改字段，不接受客户端覆写内部审计/阻断状态 |
| 现有人员校对、错误下载、提交接口 | 统一修订检查、范围复核和错误契约；继续使用现有批次回执 |

参数精确定义、长度上限和错误响应在对应实施阶段同步到 `src/api.ts`、`src/types.ts` 与HTTP测试；人员子集采用有界请求，超出URL长度时使用新增POST模板生成入口，不静默截断。保留现有GET调用兼容。

## 10. 大文件与容量（第三阶段，独立验收）

- 保留80MB为当前文件体积上限，不将其解释为可无条件同步处理的工作簿规模。
- 在转成完整矩阵之前检查每表范围；增加整个工作簿的总行数、有效单元格与解析资源预算，防止多张表分别不过限却合计过大。具体阈值由隔离基准结果配置并在页面展示，不凭文件字节数推断安全。
- 大文件采用受限并发的后台解析任务，页面展示排队/解析/校验/可审查/失败；进度只呈现可测阶段和已处理数量，不伪造百分比。
- 后台任务与业务批次状态分开，重启后能识别中断并安全重试；任务失败或取消不能改变已有正式数据及旧草稿。
- 预览改为服务端分页和筛选；批量“全部”操作明确针对服务端匹配全集；冲突组成员不可因分页被拆散导致误判。
- 原始上传文件如需持久化，使用私有目录、受限权限及明确保留/清理配置；不得通过静态URL暴露，任务完成后按配置清理，不把Excel内容或身份信息写入日志。
- 记录技术耗时、行数及错误类别即可；本期不增加导入监控看板或新的队列服务依赖。
