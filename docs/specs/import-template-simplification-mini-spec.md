# 导入模板简化 Mini Spec

日期：2026-10-22。状态：已实施，自动化验证随实现交付；WPS已核验表头、冻结、默认隐藏、分组展开及输入提示，Excel原生交互尚未核验。

## 1. 目标与范围

让教练、队务和测试人员只填写实际掌握的原始数据：常用项在前，专业选填项默认折叠，每列就地说明必填性、单位和示例；能预填的不重复录入，能计算的不要求手算。

覆盖所有现有下载入口：队员资料、训练记录、测试成绩、统一数据模板，以及独立的体能训练结果、专项训练成绩模板。保留现有上传、人员确认、数据审查、事务提交和权限边界，不新建导入业务链路。统一导出仍保留完整原始字段，不以简化为由丢失数据。

现状依据：`shared/data-import-template.ts`、`server/data-import/template-workbook.ts`、`server/data-import/data-import-routes.ts`、通用导入解析器，以及 `server/strength/strength-training-routes.ts`、`server/special/special-training-routes.ts` 和两份独立静态模板。现有统一模板已经支持人员预填、部分字段说明和缺失值处理；本规格补齐逐列说明、最小填写集、折叠和各入口一致性。

本规格独立实施模板范围，是现有 `openspec/changes/simplify-coach-data-import/` 的细化补充，不替代其人员匹配、冲突处理和数据完整性规划；该变更仍标记待实施，不能视为已上线能力。

## 2. 工作簿交互

- 继续提供三类常用模板，统一模板作为完整入口；不再要求用户先理解数据库字段或指标代码。
- 每张业务表按“人员与日期 → 最小业务必填项 → 常用选填项 → 专业选填项 → 系统预填/计算说明”排列。身份信息保留在左侧；任何条件必填列不得藏在专业折叠区。
- 专业选填列在右侧连续分组，默认收起，提供 Excel 列分组按钮及级别“2”展开，并在说明行写明操作；WPS 同样应能展开。不支持分组的客户端允许用取消隐藏访问，不能依赖宏。
- 第1行为标题，第2行为本表规则，第3行为稳定字段名；把必填标记、单位、示例、条件和数据来源作为第3行单元格的多行说明及批注。第4行开始录入，冻结前3行及身份列。解析按字段标识/受控别名映射，不能按重排后的列序硬编码。
- 每列必须包含五类文字之一：`必填`、`条件必填`、`选填`、`系统预填`、`系统计算`。标记不能只靠颜色；测量数值标明单位，日期写格式，枚举写可选值和含义；文字列不重复显示“无单位”。条件必填须直接写出触发条件，不能仅显示标签。
- 示例直接放在表头说明中，不放入可提交的数据行。独立体能模板取消“先删除示例行”的前置操作。下载空模板后直接上传不能导入示例或制造业务事实。
- 枚举用下拉及输入提示，数值用量纲提示；Excel 校验仅辅助填写，服务端仍是最终校验入口。
- “系统计算”通常不设可输入的数据列，在说明页列出公式和依赖；旧模板、完整导出中承载的原始数值继续支持，不强行移除。

表头示例：`时长分钟｜条件必填｜min｜例：60｜时长/距离至少一项`；`RPE｜选填｜无单位｜例：6｜按现有量表填写`；`系统运动员编号｜系统预填｜无单位｜系统生成，请勿自行编造`。

术语必须同时说明“是什么、什么时候填、怎么填、为什么需要、不知道时怎么办”。例如评估协议解释为评分标准名称，仅填写一般耐力/核心力量评分时需要；没有评分标准时对应评分一起留空，填写真实实测成绩即可，不让用户编造协议或版本。示例必须是具体格式，不得再用“按既有协议填写”代替示例。

## 3. 必填规则

### 通用规则

- **已有人员**：有有效系统运动员编号即可定位，姓名预填供核对；无编号时需姓名及可确定的项目、队伍上下文。有冲突或同名歧义必须人工确认，不能按姓名取第一人。
- **新建档案**：姓名、运动项目、所属有效队伍必需；项目和队伍可由下载上下文预填。出生日期、性别、手机号、技术等级等不是批量建档必填，不套用账号注册必填规则，不创建登录账号。
- **日期**：业务记录必须有有效日期，可由行内日期或上传页明确选择的统一日期提供。新模板缺少两者时阻止提交，不再静默使用今天；出生日期永不补填。旧模板既有默认策略保留，但须在审查中明确展示默认日期及来源，确认后才能提交。日期列始终可见。
- **项目与队伍**：下载时按当前授权范围预填；多队伍时需确定队伍，不猜测。文件项目与当前空间不一致、人员越权均阻止提交，不能自动改项目或调队。
- **空行**：只预填身份或统一日期、未填业务数据的行忽略；出现业务内容后才触发该业务必填校验。空白表示未提供，真实0保留；非法文本不能转换成0。

### 各业务表最小填写集

下表“必需”均以人员和有效业务日期已经确定为前提；括号中的值仅为格式示例，不是训练建议或科学阈值。

| 模板/工作表 | 必需或条件必需 | 常用选填，默认可见 | 专业项，默认折叠 |
| --- | --- | --- | --- |
| 队员资料 | 新建需姓名、项目、队伍；已有人员更新需可确定身份及至少一项实际变更 | 性别、出生日期、技术等级、备注 | 地址、民族、血型、输送信息、备战信息等现有档案字段 |
| 训练课次 | 时长min（60）或距离km（12.5）至少一项；同人同日多课时课次序号必需 | 开始时间（08:30）、训练类型、训练内容、RPE | 训练阶段、强度区间、平均/最大心率bpm、平均功率W、桨频SPM、外部来源SRPE/SMVL |
| 力量训练组次、独立体能结果 | 动作（深蹲）、实际次数（6）、实际重量kg（60）；同动作多组需组序，多课次需课次定位 | 课次名称、组序、RPE、完成状态、备注 | 计划次数/重量、强度百分比、动作代码、类别、身体部位、训练环境、组次时长/距离、强度区间 |
| 每日恢复 | 至少一项实际恢复数值或明确状态；不能只有备注 | 睡眠h、睡眠质量、疲劳、酸痛、情绪；分值含义依现有量表逐列写明 | 晨脉bpm、体重kg、状态、备注 |
| 身体测量 | 至少一项实测指标 | 身高cm（180）、体重kg（75）、臂展cm、体脂率%（15表示15%） | 肌肉量、皮褶、分段体成分、水分、相位角等现有指标 |
| 体能测试 | 至少一项实测成绩；现有规则要求方法/协议的指标必须提供协议，列始终可见 | 当前已有VO2Max（ml/kg/min）、CMJ峰值功率W等测试列及测试协议 | 备注；低频指标可按项目使用频率折叠，但不能隐藏该表全部成绩列 |
| FMS测试 | 七项中至少一项，得分为整数0—3；未测留空 | 七项分值列全部可见 | 备注 |
| 其他测试 | 指标代码或从字典选择的指标、实测值；单位优先由指标字典确定，无法确定时必须人工确认 | 指标名称、单位、测试类型、协议；字典要求侧别/协议时必填 | 目标值、测试时长min、非必需侧别、备注 |
| 伤病记录 | 伤病名称、部位 | 侧别、状态、疼痛评分、训练限制、备注 | 康复计划、复查日期 |
| 竞技评估 | 一般耐力/核心力量单项评分需评估协议；写入现行竞技状态表时还需真实总分（既有非空约束），不得编造总分 | 实际使用的评分、等级、评估协议 | 其他维度评分、备注；不要求所有维度填满 |
| 专项训练成绩（独立模板） | 项目、距离m（250）、运动员/组合、至少一轮有效成绩（0:55.15）；多人组合需完整成员 | 训练日期、艇型、性别组别、第1—3轮、时段 | 风况、地点、外部历史最好、备注 |

补充约束：

- 课次序号、组序均保持可见。单课/单组可按现有规则默认1；一旦出现多个归属候选，必须补序号或人工选定，不能静默合并到第一课/第一组。
- 仅承载有效力量组次的课次允许不填课次总时长和距离，保留未报告标志。力量组次不为方便填写而改成“每动作填总组数”，避免丢失组间重量及次数差异。
- 徒手训练真实外加重量为0时明确填0；计时或计距动作若现有模型仍要求次数/重量，不允许用编造的0绕过。纯计时训练可先用课次表记录；放宽组次模型属于后续独立变更。
- 开始时间和RPE不强制；缺开始时间的课次不能被当成有准确开训时间用于近24小时计算。缺RPE的记录可入库，但提示“无法计算SRPE”。
- 专项模板的艇型、性别组别：用于分组排名时条件必填，否则明确显示“未分组”，不可与明确分组混排。单人艇只填一次姓名；多人艇允许组合名加成员名单，不要求重复填写相同名单。没有第2、3轮不阻止导入。
- 赛艇、皮划艇、激流分别使用现有项目字典、指标适用范围和艇型；不要求激流填写桨频或平水项目协议。专项距离列用m，课次距离列用km，禁止只改标签而不处理单位。
- 伤病侧别/状态沿用现有缺省语义；疼痛评分可空，不能以0表示未提供。竞技评估只承接原始人工评价，不自动构造总分或等级。

## 4. 系统承担的工作

| 项目 | 处理规则 |
| --- | --- |
| 人员编号、姓名、项目、队伍 | 授权范围内预填；没有名单也可下载空模板；不预填任何测量结果 |
| 统一日期 | 由用户明确选择，可按行覆盖；审查展示最终日期及来源 |
| SRPE | 同时有有效时长和RPE时按现有公式“分钟×RPE”计算，单位AU；仅距离或缺RPE时保持缺失，不由距离推算时长 |
| SMVL/力量训练量 | 按现有有效组次的“实际次数×实际重量kg”汇总，遵守现有完成状态及显式总量优先策略；不把计划值当实际值 |
| FMS合计 | 七项齐全才形成完整21分制总分；部分项不补0、不生成完整总分 |
| 专项统计 | 有效轮次生成平均和最好成绩；排名及历史差值使用现有项目、距离、艇型、组别等可比条件；无可比历史时显示缺失 |
| 年龄、分析指标 | 年龄根据真实生日；冠军模型、雷达、参考值等沿用现有分析逻辑，不作为模板必填 |

历史文件或完整导出明确提供SRPE、SMVL、历史最好等原始值时，保留既有导入和冲突审查语义；计算结果与外部提供值必须区分来源，不能静默覆盖。Excel公式不是事实源，服务端负责重算应计算的结果；没有公式缓存值时不得记作0。

## 5. 实施边界

1. 在共享字段定义中补充稳定标识、必填条件、单位、示例、显示分组、来源和枚举引用，模板生成、说明与校验共用，避免文案说选填但提交报必填。
2. 优化统一构建器及两个独立模板，保留各自业务解析链路。旧表头、新表头说明、列重排均有明确映射；保持旧工作表别名兼容，不能因增加“必填”文字导致整表无法识别。
3. 新模板使用不受用户数据覆盖的版本标识；解析区分新旧规则。动态下载、静态生成及审查均读取同一版本规则；导出保留完整字段和可往返结构。
4. 只调整上述填写规则、呈现及必要校验，不迁移数据库、不新增阈值、不生成真实业务数据。正式训练事实仍写入 `training_sessions`、`daily_wellness`、`strength_result_sets`，其他业务沿用现有事实源。
5. 实施时同步README对应模板说明；说明已实现的模板规则，原生客户端尚未核验的交互不得表述为已验证。

## 6. 验收标准

- 所有六类下载入口均覆盖；打开后常用列在前，专业列默认收起且可展开，每列能直接看到必填性、单位/格式及示例。Excel、WPS分别人工验证分组、冻结、换行和下拉。
- 已预填人员与明确统一日期后：课次只填时长60即可成功，距离12.5单独填写也成功；缺RPE不产生伪造负荷。
- 新队员只填姓名、项目、有效队伍即可建档，无需生日、性别、手机号；同名或权限外人员不能自动匹配通过。
- 身体测量只填体重可导入；恢复只填睡眠可导入；FMS只填三项可导入但没有完整总分；未测值不变成0。
- 深蹲每组填实际次数6和实际重量60可导入；多组、多课正确关联。必填条件触发时，缺项错误定位工作表、行、列并说明原因。
- 专项成绩只填一轮可导入；完整组合成员可确认；跨项目拒绝，未分组不混排，秒数和时间格式转换结果一致。
- 新模板业务行无日期且上传页未选日期时阻止提交；旧模板日期回退须在审查中明确展示并确认，出生日期永不补填。
- 空模板、仅预填人员/日期的文件不创建业务事实；无需删除示例。空白、真实0、非法值分别验证，隐藏列有值也完整校验。
- 旧模板、新模板、列重排、展开后填写、完整导出再导入均不串列、不重复计量、不丢失专业字段；同人同日多课及重复导入保留现有幂等和冲突规则。
- 实施验证使用虚构数据及临时库，复用现有模板往返、导入准确性、HTTP及力量/专项定向检查；生成器变化执行模板构建与项目构建。文档交付阶段仅核对规格与现行源码，不把这些待执行验收记为已通过。
