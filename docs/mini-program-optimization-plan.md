# 竞迹微信小程序：优化与功能添加计划

> 基准：2026-09-23；依据 `docs/mini-program-analysis.md` 与 `WeChat Mini Program/` 现状。  
> 原则：不新建数据库、不绕过服务端权限、不在小程序复制高风险批量/AI 能力；每期可独立验收。  
> 与主 README、`docs/architecture.md` 冲突时以代码为准并回写文档。

## 0. 目标与不做

**目标**

1. 先消除发布阻断项与重复样板，保证真机稳定。
2. 补齐「现场可用」闭环：训练填报、档案维护、待办跟进更顺。
3. 在权限边界内增加必要的查看/协作能力，复杂编辑仍留网页端。

**明确不做（除非单独立项）**

- 微信 OpenID/手机号登录（涉及库表与账号体系）
- Excel 批量导入导出、AI 草案、账号权限配置、原始数据删除
- 引入重型图表库或第二套业务事实源

**统一验收门槛（每期）**

```text
npm run check → npm run lint → npm run test → npm run api-check（串行）
涉及页面：开发者工具手测 + 关键路径真机点检
config.js：development 仅本地；上传体验版前 production + NETWORK_DEBUG=false
```

## 1. 阶段总览

| 阶段 | 主题 | 建议周期 | 优先级 |
| --- | --- | --- | --- |
| P0 | 发布阻断与网络/配置加固 | 0.5–1 周 | 最高 |

## 2. P0 — 发布阻断与加固（立即）

### 2.1 配置发布开关

| 项 | 现状 | 目标 |
| --- | --- | --- |
| `API_ENVIRONMENT` | 仓库为 `development` | 文档化双轨：本地开发可 development；**上传/体验版检查清单强制 production** |
| `NETWORK_DEBUG` | `true` | 真机问题关闭后回 `false`；默认 false，仅联调临时 true |
| 合法域名 | 需人工 | 同一 HTTPS 域名 → request + uploadFile + downloadFile |
| `urlCheck` | 工具内 false | 仅本地；验收时关闭「跳过域名校验」复测 |

**交付**

- [ ] 小程序 README 增加「上传前 10 项检查」勾选表（config、域名、AppID、演示密码、JWT、隐私、包体积…）
- [ ] `scripts/` 可选：`mini-release-check.mjs` 静态读 `config.js`，断言上传用环境约定（或打印人工确认项）
- [ ] 真机 TLS 1.2/1.3、登录、上传照片、拉照片 三条路径 checklist

**验收**：检查表可被非开发者执行；`config` 误用 development 上传时能被流程拦住。

### 2.2 网络层加固

| 项 | 动作 |
| --- | --- |
| 超时与重试 | 写操作默认不自动重试；GET 可选 1 次幂等重试（关超时类） |
| 401 | 已有跳转；补充「跳转中不重复 toast」与 `redirecting` 单测 |
| 上传 | 失败保留 `photoFile` 可重试；成功后再清 |
| 日志 | 确认 `NETWORK_DEBUG` 下无 Token/密码/身份证/响应正文（已有脱敏，回归 `request.test.js`） |

**验收**：`npm run test` 含 request/network-error；手测断网→恢复→重试。

### 2.3 隐私与未成年人

- [ ] 隐私页字段清单：主体名称、联系方式、保存期限、投诉渠道（运营填文案，代码只留插槽）
- [ ] 发布说明：不满 14 周岁监护人授权流程归属（产品/法务，小程序可先加只读提示页）

## 3. P1 — 代码结构优化

### 3.1 抽取页面数据加载钩子（去重）

**问题**：`index` / `special` / `strength` / `profile` 重复 `onProjectChange` / `onAthleteChange` / `onRangeChange`、`loadContext`、`saveCurrentProject`、loading/error 样板；仅首页有请求序号防护。

**方案**（原生可行，不引入框架）：

```text
utils/page-loader.js（或 services/page-session.js）
  createPageSession({
    requiresAthlete, allowAllAthletes, loadMain(payload),
    defaults: { range: 'month' }
  })
  → 返回 { onShowLoad, onProjectChange, onAthleteChange, onRangeChange,
           ensureFresh, dispose 语义用序号 }
```

- 会话：`loadContext` + 项目持久化 + 运动员列表过滤。
- 并发：所有 Tab 页统一 `_seq` 丢弃过期响应。
- 首页待办保持独立方法，但共用序号约定。

**迁移顺序**：`strength` → `profile` → `special` → `index`（首页最复杂最后迁）。

**验收**：四页切换项目/时间/运动员行为与现网一致；`register` 等非 Tab 页不受影响；lint/test 全绿。

### 3.2 API 门面与查询串

- [ ] `query()` 从内联提升或复用，统一 `null/''` 过滤与编码（已有雏形）
- [ ] 每个 api 方法补一行用途注释（或集中 API 表进小程序 README）
- [ ] 禁止页面再拼 `/api/`（可用简单 lint 或 review checklist；可选 knip/自定义）

### 3.3 字典单一事实源（降低双份漂移）

| 现状 | 策略 |
| --- | --- |
| `data/register-data.js` vs `shared/projects.ts`/`regions.ts` | **维持测试对齐**（小程序不打包 shared）；shared 变更必须跑 `register.test.js` |
| `format.js` 体能指标字典 | 与网页 `strength-model` 增加「键集合」断言测试，避免漏键 |
| 角色/伤病文案 | 与 `shared/access` 等做键级抽样断言（能测多少测多少） |

**可选（有构建需求再做）**：极简脚本从 `shared/` 生成 `data/*.js`，生成物提交并测试 diff——避免运行时依赖 TS。

### 3.4 样式与误报

- [ ] 文档写明：开发者工具对 `style="…{{…}}"` 的 `css-ruleorselectorexpected` 为误报
- [ ] `app.wxss` 抽出 `.ratio-bar` 等原子类，减少各页重复
- [ ] 不强制改掉内联百分比（运行时需要）；若要消误报，可选 wxs/`dataset` 方案单独立项

### 3.5 小页卫生

- [ ] `privacy.js` 空 Page：保留，补注释「文案在 wxml」
- [ ] 登录奥运图标列表：超大数组可懒加载或裁剪未用图（结合 P3 包体）

**P1 验收**：重复 handler 行数明显下降；四 Tab 手测回归表通过。

## 4. P2 — 功能添加（现场闭环）

### 4.1 训练填报增强（ATL）

| 功能 | 说明 | 服务端 |
| --- | --- | --- |
| 课次列表筛选 | 按类型/近 7 日/本月；空态引导 | 已有 `GET /api/me/training-sessions` 可客户端过滤，优先不改 API |
| 草稿暂存 | 本地 `storage` 草稿，崩溃可恢复；不写库 | 无 |
| 校验对齐 | 与网页同规则：时长范围、RPE、距离可选 | 服务端已是权威；前端提示对齐文案 |
| 操作后反馈 | 保存成功 toast + 列表滚动到该条 | 已有 reload；可加 id 高亮 |
| 删除二次确认 | 已有 modal；补充「删除后统计会变」文案 | 无 |

**验收**：新增→总览/专项统计可见；编辑仅本人；他人账号无法进页（已前端拦 + 服务端权威）。

### 4.2 档案编辑增强（ATL）

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 表单分步/分区 | P2 | 基本信息 / 组织 / 联系 / 身体成分 四段，降低长表单放弃率 |
| 脏字段提示 | P2 | 离开未保存 `wx.showModal` |
| 照片裁剪预览 | P2 | `chooseMedia` 后先预览再传；失败可重选 |
| 身体成分「上次值」 | P3 | 读 athlete 已有值已做；补「相对上次变化」只读 |
| 身份证/手机只读完整值 | P2 | 默认脱敏；点击「修改」需服务端权限（若未支持则不做完整展示） |

**注意**：组织归属字段（项目/队伍）提交策略与服务端一致，避免越权改归属。

### 4.3 每日待办闭环（管理角色）

| 功能 | 说明 |
| --- | --- |
| 分组 Tab | 未填报 / 高负荷伤病 / 缺时间 三段锚点 |
| 点击进档案 | 已有；返回首页自动刷新（`onShow` 已拉，保持） |
| 手动刷新按钮 | 除下拉外，待办卡固定「刷新」 |
| 状态摘要条 | 已有 `todosStatus`；补失败重试按钮（`retryTodos` 已有，UI 明确化） |
| （可选）标记已知晓 | **仅本地 storage 认知标记**，不写库，避免假「已处理」 |

服务端规则（600AU、北京时间等）**不改**，只优化展示与导航。

### 4.4 总览可读性

- 强度占比：显示图例 + 点击区间 Modal（时长/百分比）
- 伤病列表：状态色块与档案页一致
- 运动员本人首页：隐藏无意义「整体」切换（已基本如此，再核对）

### 4.5 体能/专项轻量增强

| 页 | 功能 |
| --- | --- |
| 体能 | 计划练习「展开全部/前 12」；测试指标显示测试日期徽标 |
| 专项 | 运动员列表排序（负荷/课次）；冠军模型不足时引导文案到网页配置 |
| 档案 | 伤病按状态筛选 chips（本地过滤） |

**P2 验收**：每条功能有手测路径；不新增未鉴权接口；`api-check` 全绿。

## 5. P3 — 体验与包体

### 5.1 筛选组件 `scope-filter`

- [ ] 项目/运动员 picker 在加载中 disabled + 文案
- [ ] 运动员列表过长：支持首字母索引或搜索框（人数 > 50 时）
- [ ] 时间范围变更与数据 loading 的视觉统一（骨架或统一 `.state`）

### 5.2 全局状态组件

统一：loading 占位、空态、错误+重试、下拉刷新文案。  
约定 `wx:if` 优先级：error → loading → empty → content，避免嵌套过深。

### 5.3 包体与资源

| 项 | 动作 |
| --- | --- |
| 奥运 GIF | 统计大小；登录页只保留实际渲染的子集或改用静态图/雪碧 |
| TabBar | 确认 icon 尺寸与色值；避免重复 active 资源过大 |
| 分包 | 若超 2MB：`subpackages` 拆 `register`+`privacy` 或 `training-entry` |
| 压缩 | 开启工具内 minify（已有）；上传前看分包体积报告 |

**验收**：主包体积下降或明确分包方案；登录首屏可接受。

### 5.4 反馈与无障碍（工具能力范围内）

- 关键按钮 `aria-role` / `aria-label`（返回、提交、重试）
- 焦点顺序：登录表单 → 注册入口 → 隐私
- 减弱动效：避免纯装饰长动画

## 6. P4 — 能力扩展（按需，先开题再排期）

每项须先确认：**权限模型 + 服务端接口是否已有 + 是否值得进小程序**。

| 方向 | 草案 | 前提 |
| --- | --- | --- |
| 恢复日报（wellness）查看 | 只读今日/近 7 日 | 已有 API 则只加页；无则服务端只读聚合 |
| 训练计划只读详情 | 从体能页进详情（比列表更完整） | 复用 `GET /api/training-plans` 字段 |
| 消息/订阅 | 订阅消息：待办摘要、注册审批结果 | 公众平台 + 服务端订阅消息；单独设计 |
| 教练快速记伤 | SCC 记观察级伤病 | 高风险：服务端校验与权限；优先网页 |
| 导出我的档案 PDF | 仅本人 | 服务端生成或复用网页 PDF；涉敏感数据 |
| 刷脸/微信登录 | 见「不做」 | 账号体系专项 |

**P4 准入**：写一页简短设计（接口、权限、数据缓存、敏感字段）再进开发。

## 7. P5 — 质量体系

### 7.1 测试金字塔（贴合现状）

```text
Vitest 静态/单元（已有）     ← 继续：view 纯函数、payload、config、字典

开发者工具手测清单           ← 每期主路径
```

**建议新增单测**

- [ ] `buildStrengthView` / `profileView` / `buildTrainingView` / 首页 `buildView`：抽到 `utils/*-view.js` 后测空数据、缺字段、超界百分比
- [ ] `page-loader` 序号丢弃逻辑
- [ ] `personalProfilePayload` 边界（已有基础则补）

### 7.2 手测矩阵（每发版）

| 角色 | 路径 |
| --- | --- |
| ATL | 登录→总览→填报→统计变化→档案编辑→照片→改密 |

### 7.3 静态质量

- [ ] ESLint 已覆盖小程序 JS；保持 `npm run lint` 0 error
- [ ] 可选：禁 `wx.request` 直调的自定义规则或 CI grep
- [ ] `docs/architecture.md` / 小程序 README 在接口或权限变更时同步

## 10. 风险与依赖

| 风险 | 缓解 |

## 11. 建议执行顺序（一句话）

**先 M0 配置与真机，再 M1 去重 page-loader，然后 M2 填报/档案/待办三件套，M3 管包体与状态组件；P4 每项先写半页设计再进码。**
