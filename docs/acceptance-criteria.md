# 竞迹项目验收标准

> 适用范围：当前赛艇与皮划艇训练监控平台的试点交付。
>
> 验收原则：以服务端实际授权、可追溯的正式数据和可复现的聚合结果为准；前端展示或按钮隐藏不能单独作为验收依据。

## 1. 验收前提

- 使用独立的验收数据库和测试账号，不使用生产账号、真实身份证明或真实密钥。
- 至少准备运动员、队伍体能教练、项目负责人、区域负责人、训练总监、数据监控总监六类账号；准备不同区域、项目、队伍和教练归属的运动员数据。
- 验收覆盖桌面端和移动端的主要路径；浏览器控制台不应出现阻断操作的错误。
- 每个通过项均应能保存验收记录，包括操作人、时间、输入数据、接口或页面结果和必要截图。

## 2. 身份认证与账号状态

| 编号 | 验收条件 | 通过标准 |
| --- | --- | --- |
| AC-AUTH-01 | 正确账号密码登录 | 成功建立会话并进入与角色匹配的首页；后续受保护请求携带有效身份。 |
| AC-AUTH-02 | 错误账号或密码登录 | 不泄露账号是否存在、密码摘要或密钥；不建立会话。 |
| AC-AUTH-03 | 提交运动员或教练注册申请 | 申请进入待审核状态，申请人不能在审批前访问受保护数据。 |
| AC-AUTH-04 | 停用已登录账号 | 该账号下一次受保护请求被拒绝，不能继续读取、导出或写入数据。 |
| AC-AUTH-05 | 修改密码 | 原密码立即失效，新密码可登录；其他账号和数据不受影响。 |

## 3. 权限范围与组织隔离

| 编号 | 验收条件 | 通过标准 |
| --- | --- | --- |
| AC-ACCESS-01 | 运动员访问系统 | 仅能读取本人已授权的训练、测试、档案和下载内容，任何写入请求均被服务端拒绝。 |
| AC-ACCESS-02 | 教练访问运动员级资源 | 仅能读取和维护已绑定且处于授权区域、项目、队伍范围内的运动员。 |
| AC-ACCESS-03 | 管理角色访问资源 | 项目负责人、区域负责人、训练总监和数据监控总监只能在各自授权范围内管理下级、队伍和数据。 |
| AC-ACCESS-04 | 篡改请求参数 | 将请求中的 `athleteId`、项目、区域或队伍替换为无权对象时，服务端返回拒绝结果且不产生数据变更。 |
| AC-ACCESS-05 | 跨项目隔离 | 赛艇、静水皮划艇和激流回旋的数据查询、统计、导入和导出不相互混入。 |
| AC-ACCESS-06 | 审计可见性 | 数据监控总监可查看关键操作日志；日志不含密码、JWT、AI 密钥或完整敏感身份信息。 |

## 4. 运动员档案、健康与恢复

| 编号 | 验收条件 | 通过标准 |
| --- | --- | --- |
| AC-ATH-01 | 创建或维护运动员档案 | 必填身份和组织字段通过校验后保存；档案在授权列表、个人页和后续训练关联中保持同一运动员身份。 |
| AC-ATH-02 | 更新身体测量、体成分或位置数据 | 数据按测量日期归属运动员，数值校验失败时不写入。 |
| AC-ATH-03 | 上传运动员照片 | 仅接受允许的图片类型和大小；无权用户不能上传或读取他人照片。 |
| AC-HEALTH-01 | 新增伤病或恢复记录 | 记录关联正确运动员，并包含日期、状态或训练限制等可追溯信息。 |
| AC-HEALTH-02 | 健康数据访问 | 仅授权人员可见；无权人员不能通过直接接口读取、修改或导出。 |

## 5. 训练场次、负荷与体能计划

| 编号 | 验收条件 | 通过标准 |
| --- | --- | --- |
| AC-TRAIN-01 | 录入专项训练场次 | 合法的日期、项目、运动员和训练内容写入正式训练场次；无效数值、无权对象或跨项目数据被拒绝。 |
| AC-TRAIN-02 | 查看训练记录与总览 | 日期范围、项目和授权范围生效；结果可追溯至训练场次、恢复记录或力量结果等来源。 |
| AC-TRAIN-03 | 创建四周力量计划 | 教练及以上角色可创建；运动员只能查看本人已确认计划。 |
| AC-TRAIN-04 | 更新力量项目执行结果 | MAX、组数、次数、百分比和实际完成次数受格式与范围校验；实际均重及雷达图随结果一致更新。 |
| AC-TRAIN-05 | 删除历史计划 | 仅有权限的角色可删除，删除后数据不再出现在常规列表，并留下审计记录。 |
| AC-TRAIN-06 | 训练事实源 | 新增训练事实只进入 `training_sessions`、`daily_wellness` 或 `strength_result_sets`，不得新增对旧 `training_records` 的读写依赖。 |

## 6. 导入、校验与数据提交

| 编号 | 验收条件 | 通过标准 |
| --- | --- | --- |
| AC-IMPORT-01 | 下载模板 | 模板字段、示例和当前导入规则一致，可被系统重新识别。 |
| AC-IMPORT-02 | 上传训练或专项测试文件 | 系统先生成预览，展示可导入项、错误项、匹配状态和冲突信息；预览阶段不得写入正式数据。 |
| AC-IMPORT-03 | 修正预览项并提交 | 仅通过校验且在授权范围内的数据进入正式库；提交过程具备事务性，不产生半成功写入。 |
| AC-IMPORT-04 | 姓名与指标匹配 | 可匹配时关联正确运动员或指标；歧义、缺失或跨项目项需显式处理，不能静默归属。 |
| AC-IMPORT-05 | 导入审计 | 已提交批次可追溯上传人、时间、来源、处理结果与冲突策略。 |

## 7. 测试、竞技表现与分析

| 编号 | 验收条件 | 通过标准 |
| --- | --- | --- |
| AC-PERF-01 | 创建专项测试事件及成绩 | 事件、项目、日期、距离/艇型和运动员成绩的关联正确；成绩只在授权范围内可见。 |
| AC-PERF-02 | 维护力量测试与体测指标 | 指标与测试日期、运动员和单位保持一致；不完整数据明确显示为未测试，而非按零值计分。 |
| AC-PERF-03 | 查看冠军模型或个人评价 | 评分、目标差异、参考数据和缺失数据提示可解释；未经确认的参考阈值不得伪装成全国统一标准。 |
| AC-ANALYSIS-01 | 打开总览与个人分析 | 图表、汇总值、样本数、日期范围和数据覆盖率与底层授权数据一致。 |
| AC-ANALYSIS-02 | 无数据或数据不完整 | 页面显示明确的空状态、未测试或覆盖不足提示，不出现误导性零值、虚构趋势或崩溃。 |

## 8. AI 建议与设备连接

| 编号 | 验收条件 | 通过标准 |
| --- | --- | --- |
| AC-AI-01 | 生成训练建议 | 服务端使用授权范围内的运动员、训练和测试上下文生成可编辑草案；AI 密钥不出现在浏览器、接口响应或日志中。 |
| AC-AI-02 | 确认 AI 计划 | 保存前重新校验权限、日期、项目、行数、结构和数值；不符合规则的 AI 输出不得写入正式计划。 |
| AC-AI-03 | AI 服务不可用 | 返回可理解的失败或明确标识的规则草案；不得静默写入虚构正式数据。 |
| AC-DEVICE-01 | 蓝牙连接页面 | 未连接、授权拒绝、断连和不支持浏览器时有可恢复提示，不影响其他业务功能。 |
| AC-DEVICE-02 | 设备数据边界 | 未经过协议标准化、质量校验、运动员/场次绑定和人工确认的原始设备数据不得进入正式分析。 |

## 9. 导出、界面与可靠性

| 编号 | 验收条件 | 通过标准 |
| --- | --- | --- |
| AC-EXPORT-01 | 导出训练计划、Excel 或 PDF | 文件仅含当前用户有权访问的数据，姓名、项目、周期和训练内容与页面或正式记录一致。 |
| AC-EXPORT-02 | 导出失败处理 | 无数据、无权限或生成失败时给出清晰提示，不生成空白但标记为成功的文件。 |
| AC-UI-01 | 主要业务路径 | 登录、查看总览、维护档案、创建计划、导入和导出在桌面与常用移动宽度下可完成，无关键控件不可达。 |
| AC-UI-02 | 状态反馈 | 加载、保存、校验失败、权限不足和空数据均有明确反馈；重复提交不会产生重复正式记录。 |
| AC-REL-01 | 服务重启后的数据 | 已提交的正式业务数据仍可读取；仅进程内导入预览令牌失效时，系统明确要求重新上传。 |
| AC-REL-02 | 基础质量检查 | `npm run check`、`npm run build` 及与本次功能相关的定向检查均通过；无法执行的检查须在交付记录中说明原因。 |

## 10. 验收结论规则

- 所有标记为安全、权限、数据写入、导入提交或导出的条目必须通过，才能进入试点。
- 仅影响视觉细节且不阻断主流程的问题可记录为限期修复项；不得以此掩盖数据错误、越权访问或不可追溯写入。
- 任何发现的跨项目数据泄露、越权读写、错误归属、密钥泄露或未经确认的 AI 正式写入均视为阻断问题。
- 验收完成后，应将未通过项、复现步骤、影响范围、负责人和复验结果记录到发布或测试跟踪系统。
