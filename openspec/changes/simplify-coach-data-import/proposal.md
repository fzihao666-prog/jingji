# 简化教练数据导入并保证预览与入库一致

## Why

教练使用下载模板填入队员资料后，当前链路仍存在校对值与入库值不一致、重复策略未覆盖档案、空白更新覆盖历史数据、同名识别歧义及预览与提交校验不同等问题。需要先保证数据准确和可追溯，再减少重复填写、重复选队和逐条校对，使常规导入可以在一次上传检查后确认完成。

## What Changes

- 统一解析、校对、预检和提交使用的领域数据与校验规则，保留真实 0、空白与无效值的区别，阻止非法日期、错项目及有内容但无姓名的行被静默接受或丢弃。
- 采用权限内系统编号优先、项目与队伍内姓名辅助的人员识别；同名歧义显式处理，不自动重复建档，不把整批同名人员一并重新绑定。
- 默认补全空缺且保留已有非空值；覆盖已有值须展示字段差异并显式确认。档案、测量、恢复、训练与测试执行统一语义；此次不提供清空已有字段的能力。
- 提供队员资料、训练记录、测试成绩三类用途模板，按授权项目/队伍预填最小名册与系统编号；保留统一模板高级入口及既有模板兼容。
- 合法队伍自动带入；新建人员、修改已有档案、普通业务记录分别确认；将“待审核”文案改为“待确认”，不增加上级审批。
- 增加异常优先的分页校对、错误文件下载、明确的统计与提交回执；批次保留 `reviewing` 等既有状态值。
- 区分继续校对与重新解析；不同上传者不因文件哈希互相阻断或共享数据，使用正式业务键检测重复并保证重复提交幂等。
- 增加批次修订校验与事务内权限/冲突复核，处理预览后撤权、数据变化、并发确认等情形。

## Capabilities

### New Capabilities

- `data-import-integrity`：统一领域数据、校验与校对、人员归属、冲突合并、事务和权限安全。
- `coach-import-workflow`：用途模板、预填名册、最少确认、分页纠错、重传和结果反馈。

### Modified Capabilities

无现有 `openspec/specs/` 主规格可修改；新增上述 delta。兼容既有 `coach-team-responsibility` 变更的队伍派生责任关系，不恢复逐人教练关系。

## Impact

- 服务端：`server/data-import/data-import.ts`、`data-import-routes.ts`、模板生成/导出逻辑、必要的独立校验与人员解析模块；复用既有权限、字典和正式业务服务。
- 契约与网页：`src/api.ts`、`src/types.ts`、`src/pages/DataImportPage.tsx`；跨端纯类型或规则放 `shared/`，数据库逻辑仍留在 `server/`。
- 数据库：新增批次修订/解析上下文和显式确认记录所需的最小字段，调整文件哈希唯一约束；幂等迁移保留历史批次、主键和业务数据，不全库重建。
- 模板：`scripts/build-data-import-template.mjs`、`public/templates/`，保持构建产物与模板版本一致；不导出真实历史测量供填空，不引入身份证字段。
- 验证：定向单元、隔离 SQLite 集成、API 权限/并发和浏览器关键流程；同步 `README.md`、`docs/architecture.md` 的已变更事实。
- 不新增外部服务或应用运行时依赖，不使用 AI 推断真实测量，不批量清洗历史正式记录，不新增导入回滚或上级审批。当前变更仅生成待执行规格，全部实施任务保持未完成。
