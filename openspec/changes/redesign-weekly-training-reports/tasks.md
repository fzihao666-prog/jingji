# 实施任务

> 本次为规划文档，所有实施项保持未完成。实施前阅读同目录 proposal、design 和主规格，既有代码不等于已满足验收。

## 1. 契约与类型隔离

- [ ] 1.1 在现有 `shared/team-weekly-*` 定义专项/体能报告类型、阶段/补充输入、章节可用性、比较状态与确认快照契约，明确旧混合请求兼容。
- [ ] 1.2 按类型复用正式课次、计划、测试与力量组聚合，保留项目/队伍/运动员授权及缺失/真实0；代表性数据验证两类内容不混用。
- [ ] 1.3 自动选择同口径上周对比，覆盖无上周、部分缺失、上周0、人员范围改变、测试协议未知与训练阶段变化；不引入手动比较设置。

## 2. 一键生成与教练补充

- [ ] 2.1 精简报告页为类型、当前范围、默认上一完整周及折叠选填区；教练只需一键生成，阶段/文字/照片均可空。
- [ ] 2.2 在已有必要发送授权下编排统计、图表、AI为一个生成动作；将允许发送的教练训练补充实际纳入模型输入，身份/健康内容保留本地，明确不可发送段的反馈。
- [ ] 2.3 使AI起草完整周概括及分主题分析，区分统计与观察；与统计矛盾给出简短提示，缺背景不补造原因。
- [ ] 2.4 验证未配置、限流、超时、取消、错误模型输出及权限/事实变化；始终保留可编辑基础稿，不把AI作为保存的硬前提。

## 3. 图文布局与全员可读性

- [ ] 3.1 按design首页与正文顺序重排网页预览和PDF，避免主界面仍是表单字段与数据长表堆叠。
- [ ] 3.2 配置专项项目有效主图、体能重点动作图及七天课表；正文突出本周重点，完整明细归附录。
- [ ] 3.3 全员同指标合图，名单稳定排序，多人数自动两列/分组/续页；测试无截断、姓名可读、不跨指标或条件连接。
- [ ] 3.4 关闭无数据项的空图、空表和独立章节，集中一句话说明；完成文案直接编辑、可定位错误与保存下载动作。

## 4. 确认快照和同键替换

- [ ] 4.1 设计并实现独立队伍报告持久化及幂等迁移，覆盖重复初始化、原个人报告与正式事实保留、备份和回退。
- [ ] 4.2 实现唯一业务键、事实指纹复核及防丢修订，原子替换确认稿；失败与过期页面不得覆盖旧稿或较新确认结果。
- [ ] 4.3 新增分页历史查询、按类型/队伍/周期查看和基于保存快照下载；原训练补录不自动重算历史。
- [ ] 4.4 在历史、替换、下载与附件接口复用当前权限复核，覆盖范围收紧和历史包含已不可见队员的拒绝路径。

## 5. 可选照片

- [ ] 5.1 复用现有上传/压缩技术实现独立私有训练附件，完成真实格式、解码资源、方向、元数据、自动压缩及失败提示。
- [ ] 5.2 支持选择/移除与按比例自动排版，无照片不显示附件页；不接入证件照、不外发AI、不保留重复原图。
- [ ] 5.3 确认事务关联附件引用，替换后仅清理无引用旧文件；验证失败回滚、临时回收和数据库/附件备份一致性。

## 6. 验证与交付

- [ ] 6.1 运行上述领域和接口定向测试、必要类型及静态检查；复核原个人报告及现有消费者。
- [ ] 6.2 用两类报告、少/多队员、完整/缺测、长教练补充、带/不带照片、AI失败等合成样例验证；逐页检查中文PDF、图文一致性、无孤立标题及无不可读压缩。
- [ ] 6.3 对照主spec验收清单检查，并同步 README、架构与部署/备份说明；未实操浏览器及未调用真实模型的限制如实报告。
- [ ] 6.4 按项目规则仅提交本变更文件到本地，不自动push；未经新指令不在本规划任务启动实施。
