# 重设计专项与体能训练周总结

## Why

教练需要低操作成本地生成面向领导汇报和信息管理的周总结。当前周报虽然已有部分统计、AI 点评与图表代码，但尚未按专项/体能形成独立模板，教练补充没有进入AI输入，也缺少确认报告历史、自动选取对比和可选照片附件。上一版将大量统计依次展开，未形成参考PDF中的“训练概括—图表依据—问题—下周安排”的阅读结构。

本次规格以本轮需求讨论为准，既有实现只是可复用基础，不代表用户已经认可成品布局。

## What Changes

- 在既有“数据管理 → 报告”提供专项、体能两类独立周报，沿用项目/队伍并默认上一完整自然周。
- 简化为“选择报告类型 → 一键生成 → 预览核对 → 保存并下载”；训练阶段、教练观察和照片均为折叠区选填项。
- 首页突出周训练概括，正文用紧凑图表和必要分析支撑，完整全员明细收于附录；无数据项仅一句话说明。
- 系统自动选择同口径的本周/上周对比，不增加教练配置；全员对比按指标合图，不逐人独占一图、不截断人员。
- AI结合系统已算好的统计和允许发送的教练训练补充起草，允许直接编辑；记录不足时不编造结论，失败时保留基础报告。
- 确认后保存文字、数据、模板版本和压缩照片引用；同项目/队伍/周/类型替换上一份，不保留用户可见多版本。
- 照片选填，自动压缩排版；按需生成PDF，不将所有历史PDF长期加载或重复存储。

## Capabilities

### New Capabilities

- `weekly-training-reports`：报告类型、领导汇报布局、自动生成与对比、教练补充、AI、照片和确认快照历史。

### Modified Capabilities

- 无对应主规格；本次创建新增 delta 规格，与现有个人报告区别对待。

## Impact

- 网页：`ReportsPage`、`TeamWeeklyReportPreview`、报告样式及 `src/api.ts`。
- 跨端纯契约：`shared/team-weekly-*`；服务端：`server/report/team-weekly-*`、现有AI配置、权限与图片处理。
- 新增持久化能力需通过既有SQLite幂等迁移机制实现；不得复用要求 athlete_id 的个人报告表硬塞队伍记录。
- 复用现有 `sharp`、`multer`、`jsPDF` 和中文字体，无新增外部服务的需求。
- 历史、附件、AI外发内容及替换并发需专项验证，实施时同步 README 和架构文档。
- 本次只交付规格、设计与任务清单，不修改业务代码或数据库。
