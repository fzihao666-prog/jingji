# Delta 规格：健康与恢复（health-and-recovery）

## ADDED Requirements

### Requirement: 小程序状态检测页结构

小程序状态检测页（重塑恢复日报页）SHALL 按「今日状态 → 填报入口 → 状态指标 → 近期趋势 → 历史记录」组织模块；教练视角 SHALL 追加队伍状态概览（应填报、已填报、未填报人数及需要关注的人员）。今日状态 SHALL 仅使用填报状态口径（已填报/未填报），SHALL NOT 输出未经验证的医学判断标签。

#### Scenario: 今日状态与填报入口

- **WHEN** 运动员当日尚未提交恢复日报
- **THEN** 今日状态显示未填报，并提供「今日填报」入口；已提交时入口为「修改今日记录」

#### Scenario: 教练队伍概览

- **WHEN** 教练打开状态检测页
- **THEN** 展示权限范围内应填/已填/未填报人数，自评需要休息/关注或存在高负荷、伤病的人员进入需要关注名单

### Requirement: 状态指标双列展示

状态检测页 SHALL 以两列指标卡展示：睡眠时长、晨脉、体重、主观疲劳、肌肉酸痛、RPE；数值、单位与日期清晰区分。RPE SHALL 作为训练课次的主观用力评分单独展示，SHALL NOT 与晨间疲劳评分混为一个字段。数值为 0 时显示 0，缺失显示 `--`。

#### Scenario: 缺失与零值

- **WHEN** 某日体重未测量而睡眠时长为 0（异常录入被服务端校验拒绝）或有效 0 值出现
- **THEN** 缺失字段显示 `--`，真实 0 值显示 0，不互相冒充

### Requirement: 单指标恢复趋势

状态检测页 SHALL 提供指标切换「睡眠 | 晨脉 | 体重 | 疲劳」，一次仅展示一个指标的趋势图；SHALL NOT 将不同单位绘制在同一坐标轴。`GET /api/athletes/:id/wellness-trends` SHALL 在既有趋势项之外返回 `fatigue`（疲劳，源自 `daily_wellness.fatigue_index`）趋势项，点数据形状与既有趋势项一致，既有键与口径不变。

#### Scenario: 趋势切换

- **WHEN** 用户从「睡眠」切换到「晨脉」
- **THEN** 图表仅展示晨脉序列（bpm），坐标轴与单位随之更新

#### Scenario: 疲劳趋势可用

- **WHEN** 客户端请求 wellness-trends
- **THEN** 响应含 `fatigue` 趋势项且与 sleepHours 等项同形状；旧客户端忽略新增项不受影响

#### Scenario: 无数据指标保持可见

- **WHEN** 某指标在所选范围内没有数据
- **THEN** 该指标切换项仍可点击，图表区显示空状态
