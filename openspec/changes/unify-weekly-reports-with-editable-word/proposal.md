# 统一综合训练周总结并导出可编辑 Word

## Why

教练需要一份汇总专项与体能、侧重体能的完整周总结用于领导汇报和资料管理，而不是先选择两类报告。现有 PDF 不能方便地继续修改，成品需要支持在 Word 或 WPS 中修改文字、表格、图表数据与样式，同时保持一键生成的低操作成本。

## What Changes

- **BREAKING** 新生成报告统一为综合训练周总结，删除专项/体能选择；本轮决策取代 `redesign-weekly-training-reports` 中新报告类型分离、按类型下载 PDF 的要求，旧确认稿保留原样。
- 统一周概括与七天课表，专项和体能并列组织、体能分析更充分，不设置固定篇幅比例；继续遵守项目隔离、统计口径和自动比较规则。
- 正文固定展示卧拉、卧推、深蹲、硬拉，不自动选动作、不显示选择或替换入口。无对应记录时仍保留原生空图和完整内嵌数据表，数值留空供下载后补填，其余动作和全员数据进入附录。
- 默认交付 `.docx`，包含原生可编辑文字、表格、图表和文档内嵌的数据表，不将图表或整页转换为图片。
- 采用“点击生成 → 直接下载Word”，阶段、教练观察和照片选填；AI结合可发送的训练补充生成完整概述，失败仍可使用基础报告。
- 系统不保存新报告，删除在线预览编辑与历史读写代码。教练本地修改无需上传或同步，且不改动正式训练记录；正文和其他表格不会自动跟随本地修改的图表数据更新，由教练自行核对。
- 新报告不提供 PDF 格式选择；删除旧PDF、预览与历史接口。照片随生成请求压缩内嵌，不持久化；旧存量资源保留备份保全。

## Capabilities

### New Capabilities

- `weekly-training-reports`：综合周总结、一键生成并下载、体能重点布局、固定四动作、原生可编辑 Word、请求内照片处理。当前 `openspec/specs/` 无主规格；沿用前一变更的能力名称，避免另造近义能力。后续同步时以本轮新行为取代旧变更新报告要求，不重复合入相互矛盾的需求。

### Modified Capabilities

- 无已存在的主规格可修改。原个人报告与小程序能力不变。

## Impact

- 网页：`ReportsPage`、`TeamWeeklyReportPreview`、`src/api.ts`、报告样式及故事/测试。
- 服务端和共享契约：`server/report/team-weekly-*`、`shared/team-weekly-*`；复用正式事实、现有AI、权限与文档生成能力。
- 增加 Node 服务端原生 DOCX/图表导出能力；实施时优先复用已有 ZIP/XLSX 能力，若确需新依赖须按项目规则评估，不把本地 Python 样稿脚本当作生产运行前提。
- 取消报告保存；不清除现有旧快照、不修改原训练事实或个人报告。
- 已有六页体能 Word 样稿仅证明文档结构和渲染基础；综合报告及 WPS/Microsoft Word 的实际图表编辑兼容性仍须验收。
- 本轮实施上述代码简化，不改动正式训练事实、用户手工修改的样稿或其他无关文件。

## 最新范围调整（2026-10-30）
用户明确取消项目内正文预览、在线编辑及历史报告。最终行为为一次请求生成并直接下载Word，在本地修改；不再保存新报告或照片。此前有关确认、同周替换和历史兼容下载的规划由此取代。旧数据不清库，保留备份保全。
