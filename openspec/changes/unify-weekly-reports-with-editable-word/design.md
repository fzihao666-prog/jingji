# 综合周总结与可编辑Word设计

## Context

动机和范围见 `proposal.md`；行为合同见 `specs/weekly-training-reports/spec.md`。以下是读取当前代码后确认的基础，不将样稿或旧任务勾选视为新需求已经实现：

- `ReportsPage.tsx` 目前持有 `special | physical` 选择；生成、历史筛选、照片和保存均传递该类型。`src/api.ts` 的下载响应目前主要支持PDF与图片。
- `team-weekly-report.ts` 在单个只读事务内读取授权队员与正式事实，按类型过滤；整体统计不能简单拼接两次分类型预览，否则会重复课次、恢复、计划与队员。
- 共享快照限定 `templateVersion: weekly-v2`，计划条目目前主要暴露日期、内容、时长、距离和状态，尚不能完整呈现已有动作处方。
- `team-weekly-store.ts` 已有独立快照和照片表，唯一键为项目/队伍/周起点/类型；`report_type` 是无枚举CHECK的文本列。保存已有指纹与修订保护，历史和照片重新授权。
- 现有AI输出为五段文字；输入中只有可可靠识别的训练观察可以外发，健康数据留本地。生成后权限与事实变化有复核。
- `package.json` 已有 `exceljs`、`sharp`、`multer` 与 `jsPDF`，无已声明的生产DOCX生成器。本地Word样稿使用Python制作，不是现有Node服务端导出实现。
- `output/docx/体能周总结完整可编辑样稿.docx` 是体能版内容与可编辑图表参考；已进行结构和自动渲染检查，未完成Word/WPS分别编辑实测，且工作区可能存在用户手工修改，不能覆盖。
- `openspec/specs/` 当前没有主规格，前变更 `redesign-weekly-training-reports` 尚在changes内。本变更采用相同能力名称，后续归档时需显式处理新旧关系，不把两个ADDED版本无序叠加。

## Goals / Non-Goals

**Goals**

- 在同一事实快照中得到整体、专项、体能和必要背景数据，保证去重、单位和分类一致。
- 复用现有生成、确认、历史、AI和附件流程，仅移除不必要的类型和动作配置。
- 网页预览与Word复用同一报告模型和章节依据；原生图表及其内嵌数据、正文、附录保持生成时一致。
- 保留旧快照和原有PDF读取能力；新增综合记录与本地编辑文档互不污染。

**Non-Goals**

- 不新增训练动作推荐或替换算法、动作设置界面、在线Word编辑器、最终稿上传、同步或审核状态。
- 不把默认四动作视为科学评分、完整能力评估或适用于所有阶段的训练处方；不修改正式训练、测试、计划与个人报告。
- 不新增小程序周总结入口，不为新报告继续提供PDF格式选择，不承诺所有历史版本/移动版办公软件均具备相同图表编辑功能。

## Decisions

### 1. 综合模型从一次读取派生，不拼接两份报告

在现有读取事务中先获得同一项目、队伍、授权运动员和自然周的正式训练事实，再派生整体、专项、体能的指标、课表和分类。复用现有领域分类器与个人统计基础，但检查当前调用方，不能改变原个人报告行为。

整体课次沿既有正式课次识别口径去重；以已发布计划/课次ID等可靠键识别，不把同日同序号但不同正式课次误并。专项和体能视图分开标单位，恢复及伤病只作为背景读取一次。混合或未知分类不按内容关键词猜分时长：整体真实数值可保留，分类不强塞，明细和口径说明保留可见记录。日期、距离、时长、SRPE的有效性继续分别判断。

拒绝备选方案：分别生成旧专项和体能报告再合并，容易产生重复总量、重复观察、不同生成时点及不同权限快照。

### 2. 新综合模板与旧快照并存

内部给新报告使用 `reportType: combined` 和明确的新模板版本（建议 `weekly-v3`）。保留数据库 `report_type` 与原唯一键；所有新确认稿固定combined，因此业务效果是同项目/队伍/周一份综合稿。不删除或重命名原special/physical行，不改写旧JSON或把旧快照用最新事实重算。

新版读取采用模板版本/类型判别联合；旧v2继续用旧Schema和渲染路径，新v3使用综合模型，分开定义专项与体能分析文案。新旧内容不得通过宽松默认值假装兼容。模板及统计规则版本参与事实与快照契约，生成时间不参与事实指纹。

历史入口去掉类型选择，分页列出当前范围报告；旧记录仅增加必要的“旧版专项/旧版体能”标签区分，保留原只读查看/PDF下载。新combined行与旧同周行并存是历史兼容，不对新综合稿提供多版本管理。

### 3. 接口沿用现有路径并做明确兼容

本节是拟定契约，不是已实现接口：

| 操作 | 新综合路径及语义                                                                                        | 兼容处理                                                        |
| ---- | ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 生成 | 继续 `POST /api/reports/weekly/generate`，网页query只传project/teamId/date，缺省类型解析为combined      | 显式special/physical旧调用保持旧语义，不悄悄改成综合            |
| 保存 | 继续 `POST /api/reports/weekly/save`，接收新版综合快照、指纹、文案、照片ID、expectedRevision和confirmed | 服务端按版本验证与重算，旧类型不作为新页面选项                  |
| 历史 | 继续GET history及history/:id；新页面不传类型，按项目/队伍/可选周期分页                                  | 显式旧类型过滤可兼容既有调用，列表不预读所有正文/附件           |
| 下载 | 新增 `GET /api/reports/weekly/history/:id/docx`，仅按已确认综合快照生成Word                             | 旧v2保留history/:id/pdf与原只读能力，不把旧快照强制转换成综合稿 |
| 照片 | 继续已有photos路径，新页面不要求类型，默认combined                                                      | 已绑定旧稿的照片仍按原归属授权，不跨类型借用                    |

DOCX响应使用标准 `application/vnd.openxmlformats-officedocument.wordprocessingml.document`、安全的中文attachment文件名、no-store与nosniff。`src/api.ts` 显式支持docx响应并校验内容类型及失败JSON，不能将错误页作为Word文件保存。

下载在异步读取照片前后重新检查账号、角色、范围和修订，沿用现有原则。确认采用BEGIN IMMEDIATE、服务端最新事实指纹和expectedRevision；保存成功而下载失败时只重试下载，不重复覆盖快照。文档导出设有界并发、单次快照/图片资源预算和取消清理，复用现有限频，具体实现参数不变成用户设置。

### 4. 正文结构以教练报告为主，体能有更完整依据

新网页仅保留当前范围/日期、折叠补充、一键生成、可编辑图文预览、保存并下载Word、历史。AI必要授权沿现有机制展示，不增加逐章按钮。

| 顺序       | 阅读内容                                           | 数据依据与版式                                                                         |
| ---------- | -------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 首页       | 队伍、周期、可选阶段、完整周概述、少量关键统计     | 讲清目标、实际开展、记录支持的表现、问题和下周重点；背景不足不补造，来源说明不占据首页 |
| 周训练全貌 | 同一张七天课表，专项与体能统计、必要每日图和结构图 | 计划/实际清楚区分；仅在有可靠分项时长时出结构图，整体与分类单位明确                    |
| 专项分析   | 当前项目已有训练内容、量和同条件测试               | 围绕主要专项事实，不照搬力量图，不臆造专项标准                                         |
| 体能分析   | 重点安排与处方、固定四动作全员图及解释             | 从已有计划读取动作/负重/次数/组数/间歇；缺字段不推算，不用计划代替实际组次             |
| 恢复及下周 | 有效恢复资料、问题、已发布下周安排与观察           | 缺数据简述，健康资料不默认外发，不作医疗判断或自动处方                                 |
| 附录       | 其他动作与全员完整明细、简要口径、可选照片         | 不截断人员，避免正文重复长表，照片保持比例并按需续页                                   |

不固定页数；内容少时自然收敛，内容多时续页，不用过度缩字压成六页。参考样稿是呈现方向，用户当前手工修改的Word不是生产模板数据来源。

### 5. 固定动作及一致图表模型

共享纯字典固定顺序为卧拉、卧推、深蹲、硬拉。仅用已有规范动作映射匹配，动作变式、单位或条件不同不能通过模糊字符串合并；不存在对应结果时用一句说明，不出空图，也不自动拿其他动作替代。其他动作在附录按原有名称及单位展示，包含自重或按时长记录的训练，不强折公斤容量。

同一动作图包含当前授权范围全部队员，缺失标缺失、不填0。名单固定排序，人数多时共享同一动作坐标域并自动分组/续页。比较规则复用现有人员与覆盖检查，适用时加上周系列，不可比时仅本周；不为满足双系列格式而补0或外推。统计、图表数据、图下注释、附录和内嵌工作簿由同一确定模型派生，保持生成时一致。

默认动作仅是报告展示选择，研究没有证明其周容量能直接预测能力；不增加研究阈值、冠军线或动作推荐模块。

### 6. 原生DOCX和内嵌工作簿

采用Node服务端DOCX导出模块，输出真实段落、表格、内嵌JPEG照片和标准DrawingML图表，图表携带内嵌XLSX及有效数据引用和缓存。优先利用已有ExcelJS生成工作簿；ZIP/文档封装需通过显式、维护中的依赖或受测试实现完成，不依赖未声明的传递包或用户本机办公软件。若新增依赖，先审查许可、安装脚本、维护和体积，再实现。不将Python样稿生成器、LibreOffice、Word/WPS安装为生产导出前提。

备选方案：图表图片最容易导出但不满足编辑要求；HTML另存Word或把PDF转图片也不满足；在网页做完整办公编辑器会增加维护和操作成本，均不采用。

兼容处理采用简单二维柱/条/折线图，不使用宏、外部数据链接或专用插件。照片内嵌而不是链接私有下载地址；文本写入需做XML转义和非法字符清理，队员名、计划和教练文字不得成为外部关系或公式。工作簿文本写为字符串，不生成由用户内容构造的可执行公式，导出只读现有私有附件。

本地修改范围明确：改图表工作簿更新对应图表，不自动重算正文、附录、其他图表或系统快照。附简短编辑提示；不新增上传最终文件的接口或同步流程。

### 7. AI、安全与存储沿用成熟边界

AI输入分列综合统计、专项和体能，明确各单位和缺项；输出周概括、专项/体能分析与下周安排，数值仍由服务端计算。教练允许发送的训练观察实际进入输入，无法可靠分离的文字保留本地；不因为需要更丰富文案而解除身份/健康外发约束。已有保守词表可能限制可外发内容，应验证提示是否准确，而非声称所有自由文字都进入模型。

保存仍是人工确认生成内容，不写正式训练事实；AI失败返回基础稿。照片复用当前真实格式/大小/解码、缩放、元数据清理、私有归属、配额和临时回收机制。导出文件按需生成，不长期重复落盘。现有数据库和确认照片备份策略继续使用，新combined及v3数据须覆盖备份/恢复兼容验证。

## Risks / Trade-offs

- [WPS与Word版本差异] → 先做原生图表薄片验证，再扩展成综合报告；记录被测桌面版本及编辑/保存/重开证据。结构正确与LibreOffice渲染不能代替两款软件实测，不能降级为图片却宣称满足要求。
- [旧Schema拒绝新类型或旧稿读取失败] → 判别联合、版本分派和旧新混合历史测试；不直接替换旧Schema。
- [合并重复统计或混合课误分类] → 同事务事实集合、正式标识去重、整体/分类边界代表性测试；无法分项不推算。
- [固定四动作并不覆盖所有训练重点] → 依用户要求固定，不显示替换；其他动作放附录。无记录简述，不自动推荐。
- [文案缺背景仍可能空泛] → 从已有处方与可发送观察组织叙述，AI失败基础稿保留事实；不编造专业原因填篇幅。
- [本地修改产生正文与图表差异] → 生成时一致，下载提示教练自行核对；用户已接受不自动联动，不追加复杂公式或同步模块。
- [大队伍与图片导致资源压力] → 全员分组与自然续页、压缩照片、分页历史、有界导出并发，不通过截断队员控制大小。

## Migration Plan

1. 实施前备份现有数据库与对应私有确认照片，确认恢复资料完整；以合成库验证旧表幂等初始化及combined新行并存。
2. 先完成新版类型/模板判别和旧快照读取兼容，再接入综合聚合与Word生成；旧type列无需删除或变更已有行。
3. 同步部署新API与网页：新请求省略类型默认combined，旧显式调用保留分型语义；按周保存只替换combined行。
4. 验证旧PDF、原个人报告、照片与备份回归，更新README和架构/备份说明。
5. 回退时保留新增综合行与附件，不让旧应用读取无法解析的新行；若回退版本缺少版本过滤，须先提供兼容读取保护，再回退网页/业务逻辑，不能以删combined数据实现回退。
6. 后续同步主规格时，本变更的新报告要求优先；旧变更保留实施历史，并在归档说明中注明其类型分离/PDF新建流程已由本变更取代，不同时把冲突要求合入主规格。

## 验证边界

本次规划没有进行产品代码、数据库或真实AI调用验证。样稿仅提供布局与原生图表结构参考，WPS/Word编辑兼容性列为实施验收项；环境无法实测时必须标注未验证，不伪称通过。本次不自动启动实施。

## 2026-10-30 用户指定的最终成品布局

按用户提供的五章模板落实：01本周训练概览（核心指标及目标完成评价）；02训练计划与执行（七天上午/下午/恢复课表、时长负荷与分类图、计划实际并列）；03重点训练及运动员表现（专项、体能、固定四动作容量及全员同动作对比）；04状态恢复及风险（RPE、睡眠、疲劳、晨脉各自单位、已知异常及综合评价）；05下周目标、安排、监测和教练总结。附录完整保留计划处方、全员事实、可选照片及口径。

封面为竞迹专业运动队训练周总结报告，A4竖版、20mm页边距、深海军蓝标题、专业蓝图表、10pt中文无衬线正文。正式字段不新增填写门槛：未知地点、负责人、目标、调整原因明确未记录，下载后自行补充；周次为ISO日历周，生成日期按上海时区。恢复与未分类不强拆为恢复时长。强度无可靠分区时仅展示既有训练分类。继续采用可编辑Word，不改回PDF，不自动挑选重点人员或替换固定动作。
