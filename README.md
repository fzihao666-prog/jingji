# 竞迹｜赛艇与皮划艇训练监控平台

面向全国、省、市、区县和队伍的网页端训练数据系统。教练将汇总后的Excel上传到系统，系统完成字段校验、权限校验、训练日历展示、周期统计与PDF报告生成。

## 当前已实现

- 系统品牌统一为“竞迹”，登录页、侧栏、浏览器图标、个人档案、周期报告和Excel导出均使用GFC标识；
- 五级六类角色：运动员（ATL）、队伍体能教练（SCC）、项目负责人（PRJ）、区域负责人（REG）、训练总监（TD）、数据监控总监（DMD）；
- 所有账号同时绑定上级账号、行政区域、项目和队伍；
- 服务端按“角色 × 行政区域 × 项目/队伍”过滤数据，前端隐藏按钮不作为权限依据；
- 运动员/教练注册申请和授权范围内的上级审核；
- 一个运动员绑定多名教练；
- 教练只能读取、导入自己负责的运动员；
- 运动员只读本人数据；
- 上级只查看和管理管辖范围内的下级，同级区域之间隔离；
- 项目负责人和区域负责人按授权项目或区域管理队伍；
- 训练总监管理管辖区域全部训练岗位和训练数据；
- 数据监控总监管理本区域全部数据、账号状态和操作日志，但没有删除原始测试数据的接口；
- 权限工作台可创建下级账号、设置角色、上级、多个行政区域、项目、队伍和启停状态；
- 统一生成“行政区划代码-项目代码-角色代码-账号序号”；
- 姓名旁提供统一修改入口，并由服务端校验上下级关系和数据范围；
- 用户可以修改自己的登录密码；
- 独立“训练计划”模块：每名运动员绑定证件照，教练可维护四周力量处方；运动员只能查看本人计划；
- 每份计划最多8个训练项目，按已填写项目动态生成雷达顶点；6个项目显示六边形，不再补空顶点；
- 每个项目可手填MAX、组数、次数、百分比和实际完成次数；计划重量仍按“MAX × 百分比”计算；
- 网页和Excel的“项目”列只显示项目名称，不再混入备注、实际均重或MAX占比；
- 训练计划顶部采用左侧个人信息、右侧实际均重/MAX单系列雷达图，人体肌肉图仅作为雷达中心视觉，不显示旧标注；
- 每份个人计划统一导出为四周Excel模板，自动带入证件照、姓名、项目、组别、体重、当前项目名称和训练安排；
- 标准Excel模板下载、上传预览、逐行校验和确认入库；模板采用“一名运动员一天一行”，支持水上/测功仪 U3—ATP 距离、力量与恢复分项；
- 自定义时间范围、训练日历和每日明细；
- SRPE、SMVL、专项距离、训练结构、强度分区与恢复指标；
- 个人档案按周、按日独立下载总结PDF和训练日志PDF，文件带“齐总”水印；
- 个人档案包含正面肌肉解剖人体图、身高/臂展测量线、前侧实线/后侧虚线、教练目标差值、左右侧差异、相对力量和规则化个人评价，可独立导出A4力量档案；
- 多页A4周期报告和PDF下载；报告严格引用所选日期内的已入库数据，包含日/周负荷柱状图、水陆与主辅比例、水上强度、陆上训练类型、训练结构、个人对比和逐日训练安排；
- 桌面端与移动端响应式界面。

## 赛艇分析标准

- 当前标准版本：`GJ-ROW-2026.07-R1`；
- 沿用原模型的一般体能100分、重要基础体能160分、专项基础200分、专项成绩250分和DSD规则；
- 未发现可公开验证、可直接替换原阈值的2026统一数值分级表，因此不修改原有阈值；
- 新增6km功率/运动心率效率、血氧和艇上效率为建议监测项，先用于个人纵向比较，不作为全国统一等级；
- 未采集字段显示“未测试”，不按0分处理；
- Wingate、左右差、生理生化星级、Z-Score参考人群和综合权重等待专家确认后再启用。
- 力量测试目标值必须由教练确认；系统只计算实测值与目标值的差异，不自动生成所谓“冠军标准”。

## 本地运行

要求 Node.js 24 或更高版本。

```powershell
npm install
npm run dev
```

打开 `http://127.0.0.1:5173`。

生产构建与启动：

```powershell
npm run build
$env:JWT_SECRET='替换为足够长的随机密钥'
npm run start
```

生产模式由 `http://127.0.0.1:8787` 同时提供网页与API。

## AI训练建议

- 在“个人档案 → 力量测试个人评价”中，教练可根据当前测试和目标值生成四周训练建议；
- 未配置AI时，系统使用内置规则生成明确标注的演示草案；配置AI后自动切换为OpenAI兼容接口；
- 教练可编辑并确认方案，运动员只能查看已确认版本；
- “导出建议PDF”包含力量对比档案和训练建议两页，并保留“齐总”水印；
- API密钥仅配置在服务器环境变量中，不会发送到浏览器。

```powershell
$env:AI_BASE_URL='https://服务商接口地址/v1'
$env:AI_API_KEY='服务商提供的密钥'
$env:AI_MODEL='模型名称'
npm run start
```

## 注册与审核

1. 用户在登录页选择“申请注册”；
2. 运动员和教练都填写所属省、市、区县、项目和队伍；
3. 申请提交后暂时不能登录；
4. 有权限的上级账号进入“账户审核”决定通过或拒绝；
5. 项目负责人及以上岗位可在“人员关系”中维护教练和运动员关系。

## 账号权限

- 上级账号在“账号权限”中创建和管理权限范围内的下级账号；
- 行政区域支持全国、省、市和区县四级，一个负责人可以绑定多个授权区域；
- 项目支持赛艇、皮划艇或全部项目，队伍可以继续细分；
- 上级兼容下级的查看范围，但修改、审核、导出、账号管理分别由接口控制；
- 停用账号会立即使现有登录失效；
- 数据监控总监可以查看最近200条操作日志。

## 姓名修改

- 所有可修改的姓名旁显示铅笔标识；
- 每个用户可通过侧栏修改自己的姓名；
- 上级账号可在授权范围内修改下级姓名；
- 运动员改名会同步更新登录资料、训练记录显示和后续Excel姓名匹配。

## Excel导入

登录队伍体能教练及以上岗位，在“Excel导入”页面下载标准模板。系统会自动查找同时包含“日期”和“运动员”的数据工作表，不要求它排在第一张，并支持 `.xlsx` 文件。

推荐直接使用“竞迹训练数据导入模板”：总训练时长、专项距离和 SRPE 可由分项字段自动计算；水上与测功仪 U3—ATP、功能力量、力量耐力、最大力量、速度力量、拉伸再生、跑步和其他训练会进入周期报告对应图表。

必填列：

- 日期；
- 运动员；
- 训练时长（分钟）。

推荐列：训练类型、结构分类、强度区间、训练内容、专项距离、RPE、SRPE、SMVL、晨脉、体重、睡眠、疲劳指数、训练状态和教练备注。

未填写SRPE时，系统使用“训练时长 × RPE”计算。运动员姓名必须与系统名单一致，教练无法导入未绑定运动员的数据。

## 训练计划

- 教练及上级账号在“训练计划”中选择运动员、新建或更新计划，并上传该运动员的JPG/PNG证件照；
- 每份计划设置开始日期和结束日期，以28至31天作为一个月度训练周期；修改开始日期时自动生成一个月后的结束日期；
- 教练及授权上级可以删除历史计划，删除动作会记录操作日志；运动员不能删除；
- 最多维护8个项目；MAX、每周组数、次数、百分比和实际完成次数均可手工维护；
- 页面和Excel中的重量由 `MAX × 百分比` 自动计算，不需要重复录入；
- 系统按 `Σ(重量 × 计划组数 × 实际完成次数) ÷ Σ(计划组数 × 实际完成次数)` 自动计算实际均重，雷达图实时显示 `实际均重 ÷ MAX`；
- 项目名称、实际平均重量和MAX作为同一数组对象排序，保证项目与雷达顶点不会错位；未填写项目不进入雷达数组；
- “完成次数”列手工填写每组实际完成次数，修改后项目实际均重和雷达图立即联动；
- 运动员端只显示本人计划和下载入口，不显示保存按钮，服务器也会拒绝运动员修改请求；
- 每个运动员的所有导出文件使用同一版式，证件照从个人档案直接调用。

## 部署注意事项

- 当前数据库是项目目录中的本地SQLite文件，适合单机或小范围试点；正式全国多人部署应迁移到PostgreSQL并配置备份、监控和灾备。
- 登录和注册已有限流，JWT密钥会首次启动时随机生成到 `data/.jwt-secret`；部署时应安全备份该文件，或通过环境变量设置 `JWT_SECRET`。
- 正式上线前必须修改全部演示账户密码，并使用HTTPS反向代理。
- 一键下载的PDF为了稳定呈现中文采用页面渲染方式；“浏览器打印”可生成带可选择文本的PDF。
- 异常状态使用固定阈值，不调用大模型；阈值需要与教练团队进一步确认。
- 目前数据为演示数据，正式试点前应先导入确认过的数据字典和真实运动员名单。
