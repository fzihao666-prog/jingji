# 竞迹｜赛艇与皮划艇训练监控平台

面向全国、省、市、区县和队伍的网页端训练数据系统。系统提供分级权限、训练总览、体能训练、专项训练、个人档案与档案PDF导出。

微信小程序登录页、注册页及“我的”页展示小程序备案号“京ICP备2026065980号”，并提供工信部备案系统查询网址的复制入口。

## 当前已实现

- Web 训练总览的训练量统计将体能与专项合并为整行并列柱状图，统一按分钟比较每日训练时长；图例可点击或用键盘切换，并提供数据表。沿用当前项目、队伍、运动员和周期筛选及服务端团队去重/个人统计口径；缺失留空，真实 0 保留。专项距离在摘要、Tooltip 和表格展示，负荷仍在独立模块展示；仅整个周期无真实训练量数据时显示明确标记的客户端示例。

- 微信小程序“体能训练”分为概览、训练安排和训练记录：可切换已保存计划、按周和动作分类查看完整处方，按日期查询并展开逐组计划/实际结果，查看指标历史及五类训练结构占比（基础力量、功能性体能、核心力量、专项力量、代谢训练，取训练明细的训练分类，缺失时按动作名归类，0 值行保留）。继续读取现有测试、计划、体能结果接口，不新增数据库或写入接口；此页没有真实数据时显示空状态，不再使用示例柱形，冠军模型未配置时不计算对标。

- Web 与微信小程序的训练趋势、强度占比等可视化（小程序体能训练页除外）在没有真实数据时使用固定示例图形，并显式标记“示例数据”；示例仅在客户端绘制，不进入数据库、统计、排名、PB 或评价。真实数据（含部分真实数据）优先展示；测试成绩、伤病判断、人数等业务事实仍按真实记录显示。

- 微信小程序首页提供“每日训练待办”：按当前项目与服务端权限范围列出当天未填报、近24小时高负荷（SRPE 累计 ≥600 AU）及当前伤病关注运动员；支持直接进入档案，返回、下拉或手动刷新后重算；待办卡可按“全部/未填报/负荷与伤病/时间待补”分组筛选，并按姓名或队伍搜索，分组人数基于搜索结果实时重算。日期以北京时间为准，缺少开训时间的记录单独提示。使用 `npm run daily-todos-example` 可创建独立场景库，样例按正式口径参与统计；使用方式见 [小程序说明](WeChat%20Mini%20Program/README.md#每日训练待办与场景数据)。
- 微信小程序档案页可上报伤病与疼痛反馈：管理角色写入正式伤病记录，运动员只能提交本人疼痛反馈，服务端强制记为 `feedback/observation` 并丢弃状态、限制与康复计划，提交后回档案并刷新首页待办。使用 `POST /api/athletes/:id/injuries`，越权提交返回 403。
- 微信小程序运动员可通过 `/api/me/training-sessions` 填报本人训练课次；注册页只读取公开队伍名称，队伍统计接口需要登录。上线配置默认使用生产 HTTPS 地址并关闭网络调试。
- 微信小程序教练等管理角色可代运动员填报训练课次与恢复日报：训练填报、恢复日报页顶部可切换目标运动员，走 `POST/PUT/DELETE /api/athletes/:id/training-sessions` 与 `GET/POST /api/athletes/:id/wellness`，服务端复用运动员访问范围校验，`source` 记为 `coach_report` 并计入正式统计；本人填报仍走 `/api/me/*`，`source=athlete_self_report`。非授权角色或越权目标返回 403。
- 微信小程序体能、专项页提供“录入测试”入口（仅教练等管理角色可见）：现场录入体能测试指标或专项测试成绩，分别走 `POST /api/strength-tests` 与 `POST /api/special-tests/manual`，日期、数值、成绩格式和成员选择均在两端校验，服务端按运动员权限与项目范围落库。专项测试成绩默认只展示最近 3 场、每场最好 3 条并可按需展开；专项录入保存后保留赛事条件便于同一场次连续录入，按项目记忆上次条件与常用距离，主测运动员默认进成员，风况/地点/历史最好/备注收进“更多条件”折叠。
- 微信小程序训练填报、恢复日报、伤病上报、测试录入四个表单支持弱网草稿暂存：填写内容自动保存在本地（只存表单内容，不含凭证），保存成功后清除；再次进入页面若存在未提交草稿会提示恢复或重新填写。草稿按“表单 × 身份（本人/目标运动员）”隔离，教练切换运动员不会串稿。
- 微信小程序首页向运动员展示“今日状态”卡：当天是否已填报、24 小时负荷和恢复日报状态，并直达记录训练与恢复日报页面；`GET /api/me/today-status` 与教练每日待办复用同一口径。恢复日报通过 `GET/POST /api/me/wellness` 写入 `daily_wellness`（`source=athlete_self_report`，按运动员与日期幂等覆盖），支持最近 7 天回填，只保存睡眠、晨脉、体重、疲劳、酸痛、心情等自评原始数值，不生成诊断或评分；未来日期、超窗日期和空提交返回 400，非本人返回 403。
- 微信小程序教练待办新增“复查提醒”分组：最近一条非健康且填了复查日期的伤病记录，复查日期在今天起 3 天内（含已逾期）即进入待办，`dueIn` 由服务端按北京日期计算；运动员自评“需要休息”并入“负荷与伤病”关注分组并在队伍总览打标签。待办每行提供就地动作（代填训练、代填日报、上报伤病），并支持“今日已跟进”个人标记（`coach_todo_followups` 表，按用户×运动员×日期存储，只影响本人待办展示，不参与统计口径；`PUT/DELETE /api/coach/daily-todos/followups` 幂等，越权整批 403）。
- 微信小程序档案页提供按部位的“疼痛趋势”只读卡（`GET /api/athletes/:id/injuries/pain-trend`，近 30 天每日评分、同部位同日取最新一条、正式伤病与疼痛反馈都参与），点击柱体查看单日明细；伤病列表对临近复查的记录显示“今天复查/逾期 X 天”倒计时。趋势只呈现评分序列与状态，不输出诊断结论。

## 赛艇分析标准

- 个人档案雷达仅在赛艇项目启用：专项雷达固定为5个维度，体能雷达固定为6个维度；两者只读取真实、有效且非演示的测试记录。
- 冠军参考必须具备可追溯来源、来源年份和测试协议；任一当前值缺失时显示“待采集”，正式参考缺失时显示“待参考”，均不以0补齐或计算虚假对标。
- 皮划艇及其他项目的雷达维度和参考标准待单独审核与配置。
- 当前标准版本：`GJ-ROW-2026.07-R1`；
- 沿用原模型的一般体能100分、重要基础体能160分、专项基础200分、专项成绩250分和DSD规则；
- 未发现可公开验证、可直接替换原阈值的2026统一数值分级表，因此不修改原有阈值；
- 新增6km功率/运动心率效率、血氧和艇上效率为建议监测项，先用于个人纵向比较，不作为全国统一等级；
- 未采集字段显示“未测试”，不按0分处理；
- Wingate、左右差、生理生化星级、Z-Score参考人群和综合权重等待专家确认后再启用。
- 力量测试目标值必须由教练确认；系统只计算实测值与目标值的差异，不自动生成所谓“冠军标准”。

## 注册与审核

1. 用户在登录页选择“申请注册”，小程序端还可选择注册身份（运动员或教练，白名单仅此两项）；
2. 运动员和教练都填写项目和队伍；运动员注册还需手机号、身份证号（自动推导性别与出生日期）与籍贯，教练仅需手机号；
3. “系统管理 → 账户审核”顶部提供“注册审核”开关（系统管理相关角色可改）：开启时新注册进入待审核暂不可登录，关闭时新注册自动开通可直接登录；开关只影响后续注册，不批量修改历史账号；
4. 审核开启时，有权限的上级账号进入“账户审核”决定通过或拒绝；
5. 项目负责人及以上岗位可在“人员关系”中维护展示用的主管教练关系；运动员可见范围由队伍与项目权限自动决定。

## 体能训练

- 教练及上级账号在“体能训练”中选择运动员、新建或更新训练，并上传该运动员的JPG/PNG证件照；
- 手工训练默认以28至31天作为月度周期；AI生成体能训练根据教练输入的目标和周期生成安排；
- 教练及授权上级可以删除历史训练，删除动作会记录操作日志；运动员不能删除；
- 最多维护8个项目；MAX、每周组数、次数、百分比和实际完成次数均可手工维护；
- 页面和Excel中的重量由 `MAX × 百分比` 自动计算，不需要重复录入；
- 系统按 `Σ(重量 × 处方组数 × 实际完成次数) ÷ Σ(处方组数 × 实际完成次数)` 自动计算实际均重，雷达图实时显示 `实际均重 ÷ MAX`；
- 项目名称、实际平均重量和MAX作为同一数组对象排序，保证项目与雷达顶点不会错位；未填写项目不进入雷达数组；
- “完成次数”列手工填写每组实际完成次数，修改后项目实际均重和雷达图立即联动；
- 体能总览的“训练内容分析”按训练场次名称、训练结构、动作名称和既有训练分类归纳交叉训练、功能训练、拉伸再生、循环训练、最大力量、爆发力、核心力量和动作准备；水上、跑步等范围外训练不参与八类占比；
- 运动员端只显示本人计划和下载入口，不显示保存按钮，服务器也会拒绝运动员修改请求；
- 每个运动员的所有导出文件使用同一版式，证件照从个人档案直接调用。

## 部署注意事项

- 当前数据库是项目目录 `data/training-monitor.db` 中的本地 SQLite 文件，适合单机或小范围试点；正式全国多人部署应迁移到 PostgreSQL 并配置备份、监控和灾备。
- 数据库路径由 `server/core/database-path.ts` 统一解析；新库、旧库升级、备份和历史脚本的用途见[数据库说明](docs/database.md)。无需手工运行历史增列 SQL；不要删除 `data/`、数据库备份或迁移前副本。
- 登录和注册已有限流，JWT密钥会首次启动时随机生成到 `data/.jwt-secret`；部署时应安全备份该文件，或通过环境变量设置 `JWT_SECRET`。
- 正式上线前必须修改全部演示账户密码，并使用HTTPS反向代理。
- 一键下载的PDF为了稳定呈现中文采用页面渲染方式；“浏览器打印”可生成带可选择文本的PDF。
- 异常状态使用固定阈值，不调用大模型；阈值需要与教练团队进一步确认。
- 为使训练总览的六维多要素雷达完整展示，系统会为缺少数据的运动员补入与项目、性别相匹配的演示指标及近 28 天恢复数据。此类记录均带有“估算/演示”来源标记，不会覆盖导入或手工填写的真实测试数据；正式使用时应以统一模板导入的真实数据替换。
- 目前数据为演示数据，正式试点前应先导入确认过的数据字典和真实运动员名单。

小程序资料保存支持姓名与日期提交前校验、日期补零和分类型网络错误提示；线上后端须与客户端同步更新。真机连接重置的 TLS 分版本检查与验收步骤见 [小程序排障说明](<WeChat Mini Program/README.md#资料保存与真机网络排障>)。

### 体能冠军参考模型

体能训练概览复用 `radar_reference_values`，按项目（赛艇、皮艇竞速、激流）和性别提供成人开放组八维参考：相对深蹲、相对卧拉、相对高拉、纵跳、2分钟卧拉、前支撑、Wingate相对峰值功率和VO₂max。新增48项基线均标记为**估算参考**，用于训练对比，非冠军个人实测；既有标准和运动员测试成绩不会被覆盖。服务启动时自动执行兼容迁移和缺失参考补全。

页面包含参考信息、对比摘要、核心指标、冠军/团队/个人雷达、差距表和周期趋势。摘要展示可比较维度、达标项数及最低达成度维度；指标卡并列显示冠军参考与当前达成度。冠军为100%，超过100%保留。团队均值按每维有效人数计算；综合趋势仅使用全部参考维度齐备的运动员，避免缺测造成虚高。趋势使用所选周期内截至当日最近一次有效测试，附样本量；采用ECharts时间轴展示，并提供100%参考线、最新达成度、较首个有效日期的百分点变化和最新样本数。

测试必须使用卡片显示的协议及单位；力量测试可在备注中用中文分号分隔各项协议，例如 `深蹲1RM；卧拉1RM；CMJ双手叉腰`。相对力量需要同一次测试的有效体重；无协议、协议不同、演示或估算测试均不参与对标。年龄未知的普通记录及未成年人不套用成人标准；当前开放组不代表轻量级专项标准，也未提供未成年或具体小项专项参考。

仅同时拥有全国、全部项目和全部队伍权限的DMD可展开卡片“修改参考值”，修改数值、协议、来源类型和来源说明；保存持久化并记录审计，修订号防止多人覆盖。其他角色按已有运动员访问范围查看。未匹配的测试默认留空，不自动生成个人模拟成绩。
